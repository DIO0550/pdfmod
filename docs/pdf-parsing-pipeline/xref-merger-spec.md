## PDF 仕様の要点（増分更新とハイブリッド参照）

### 増分更新と `/Prev` チェーン（ISO 32000-1 §7.5.6）

PDF は既存データを書き換えずに末尾へ差分を追記できます。各 xref セクションの trailer（または XRef ストリーム辞書）に含まれる `/Prev` が、一つ前の xref セクションのバイトオフセットを指すリンクリストを作ります（`/Prev` が無いセクションが最古の末端）。

```text
+========================+
| オリジナル PDF          |  xref セクション A (offset=1000) /Prev なし
+========================+
| 増分更新 #1             |  xref セクション B (offset=2500) /Prev 1000 ──→ A
+========================+
| 増分更新 #2 (最新)       |  xref セクション C (offset=4000) /Prev 2500 ──→ B
+========================+
  ↑ startxref = 4000 から遡る
```

### ハイブリッド参照ファイルと `/XRefStm`（ISO 32000-1 §7.5.8.4）

古いリーダーとの互換性のために**テキスト xref と XRef ストリームの両方**を持つファイルでは、テキスト trailer に `/XRefStm`（相互参照ストリームのオフセット）が含まれます。

```pdf
xref                      % テキスト側（ObjStm 内オブジェクトは free または未記載）
...
trailer
<< /Size 100 /Root 1 0 R /XRefStm 5000 /Prev 1000 >>
```

**処理規則**:

1. テキスト trailer に `/XRefStm` があれば、**`/Prev` を辿る前に**相互参照ストリームを読む。
2. 同一更新内では、**相互参照ストリーム側のエントリをテキスト側より優先**する（ObjStm 内オブジェクトの `type=2` はストリーム側にのみ存在するため）。
3. チェーン継続にはテキスト trailer 側の `/Prev` だけを使う（ストリーム側の `/Prev` は辿らない）。
4. `/XRefStm` のオフセットも循環検出用の `visited` 集合へ登録する。

> `/XRefStm` を無視すると ObjStm 内オブジェクトが `null` 扱いになり静かに欠落するため、ハイブリッド参照対応は必須です。

## エントリ型の上書きルール

マージモジュールはエントリ型の遷移を検証せず、単純に**新しいセクションのエントリで上書き（後勝ち）**します。意味論的検証は上位モジュールの責務です。

| 旧エントリ | 新エントリ | 意味 |
| :--- | :--- | :--- |
| `used (1)` | `free (0)` | オブジェクト削除（世代番号 +1） |
| `used (1)` | `compressed (2)` | オブジェクトストリームへの移動 |
| `free (0)` | `used (1)` | 空き番号の再利用（世代番号 +1） |
| `used (1)` | `used (1)` | 同一番号での内容差し替え |
| `free (0)` | `free (0)` | 空きチェーン再構成 |
| `compressed (2)` | `used (1)` | 圧縮オブジェクトを個別オブジェクトへ展開 |

## 走査とマージのアルゴリズム

### 処理フロー

```text
[1] 収集フェーズ（newest-first）
    startxref → セクション C → /Prev → セクション B → /Prev → セクション A
    収集結果: [C, B, A]
        │
        ▼
[2] 反転（oldest-first）
    [A, B, C]
        │
        ▼
[3] マージフェーズ
    oldest-first の順に Map へ登録（同一オブジェクト番号は後勝ちで上書き）
        │
        ▼
[4] /Size 決定 & trailer 正規化
    - size = 全セクションの /Size の最大値
    - 最新セクション（反転前の先頭 = 反転後の末尾 C）の trailer を採用し /Size を正規化
```

### 安全ガードと境界条件

| 項目 | 仕様 |
| :--- | :--- |
| **循環検出** | 走査済みオフセット集合 `visited` に `/Prev` と `/XRefStm` の双方を記録し、既訪問オフセットへ再到達したら即座に `XREF_PREV_CHAIN_CYCLE` エラー |
| **深度制限** | 走査する xref セクション数（最初のセクションを含む）に上限（既定 **100**）を設け、超過時に `XREF_PREV_CHAIN_TOO_DEEP` エラー |
| **`/Prev = 0` の扱い** | バイトオフセット `0` は仕様上合法な値のため、truthy 判定で打ち切ってはならない。必ず「`/Prev` エントリが存在するか（未定義でないか）」で判定する |
| **`/Size` の決定根拠** | ISO 32000-1 で `/Size` は「最大オブジェクト番号 + 1」。増分更新で増加することはあっても減少しないため、全セクションの最大値を取る |

## エラーケースと形式混在

### エラーケース

すべてのエラーは `throw` せず `Result`（`Err<PdfParseError>`）で返します。

| ID | エラーコード | 条件 | メッセージ例 |
| :--- | :--- | :--- | :--- |
| E-001 | `XREF_PREV_CHAIN_CYCLE` | `/Prev` または `/XRefStm` が既訪問オフセットを指す | `"/Prev chain cycle detected at offset 1000"` |
| E-002 | `XREF_PREV_CHAIN_TOO_DEEP` | 走査段数が深度上限（既定 100）を超過 | `"/Prev chain depth exceeded limit of 100"` |
| E-003 | 下位パーサエラーの伝播 | 各 xref セクション解析でエラー発生 | `parseXRefTable` / `decodeXRefStreamEntries` 等のエラーをそのまま返却 |

### 形式混在（XM-004）

増分更新ごとにテキスト形式とストリーム形式が混在する場合でも、`mergeXRefChain` はコールバック方式でオフセットを渡すため透過的に扱えます。呼び出し元コールバックが指定オフセットの先頭バイトで形式を判別します。

| オフセット先頭のパターン | 形式 | 呼び出すパーサ |
| :--- | :--- | :--- |
| `xref` キーワード | テキスト形式 | `parseXRefTable` + `parseTrailer` |
| 間接オブジェクト定義（`N G obj`） | XRef ストリーム | `XRefStreamParser`（辞書に trailer 統合） |

## 具体例

### 例 1: 増分更新 1 回の PDF

- **セクション A（オリジナル, offset=1000）**: `obj 0〜5`（`obj 3` は `offset=120`）、`/Size 6`
- **セクション B（更新 #1, offset=2500）**: `obj 3` を `offset=500` へ更新、`obj 6` を `offset=600` で追加、`/Size 7`、`/Prev 1000`

1. 収集: `[B, A]` → 反転: `[A, B]`
2. マージ: A の `0〜5` を登録後、B の `obj 3 (offset=500)` で上書きし `obj 6 (offset=600)` を追加。
3. 最終結果: `size = max(6, 7) = 7`、`obj 3` は `offset=500`、`obj 6` が追加された状態になる。

### 例 2: 3 段チェーン（更新の後に削除）

| セクション | offset | `/Prev` | `/Size` | 変更内容 |
| :--- | :--- | :--- | :--- | :--- |
| A（オリジナル） | `1000` | なし | `5` | `obj 0〜4` を定義（`obj 2`: used, offset=74） |
| B（更新 #1） | `2500` | `1000` | `6` | `obj 2` を offset=300 へ更新、`obj 5` 追加 |
| C（更新 #2） | `4000` | `2500` | `6` | `obj 2` を削除（free, gen=1）、`obj 3` 更新 |

収集 `[C, B, A]` → 反転 `[A, B, C]` の順に適用すると、`obj 2` は `used(74) → used(300) → free(gen=1)` と上書きされ、最終的に最新セクション C の削除状態が残り、`size = max(5, 6, 6) = 6` となります。
