# オブジェクトストリーム仕様 (Object Streams)

> **上位目次**: [PDF解析パイプライン仕様](./index.md)  
> **対応規格**: ISO 32000-1:2008 §7.5.7 / ISO 32000-2:2020 §7.5.7  
> **関連仕様**: [オブジェクト解決仕様](./object-resolver-spec.md) / [02a. インダイレクトオブジェクト解決 §5](../specs/02a_object_resolution.md#5-オブジェクトストリーム内のオブジェクト) / [07. データ圧縮とストリームフィルタ §4](../specs/07_compression_filters.md#4-オブジェクトストリームobject-streams)

## 1. 概要

オブジェクトストリーム（ObjStm）は PDF 1.5 で導入された構造圧縮メカニズムです。複数の間接オブジェクトを 1 つのストリーム内にまとめて格納し、ファイルサイズを削減します。XRef ストリーム（`Type=2` エントリ）と組み合わせて使われます。

### 1-1. 導入バージョン

| バージョン | 仕様 | 変更内容 |
| :--- | :--- | :--- |
| PDF 1.5 | ISO 32000-1:2008 §7.5.7 | ObjStm 導入 |
| PDF 2.0 | ISO 32000-2:2020 §7.5.7 | 仕様継続（変更なし） |

---

## 2. ObjStm 辞書エントリ

| キー | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| `/Type` | 名前 | **必須** | `/ObjStm`（固定） |
| `/N` | 整数 | **必須** | ストリーム内に格納されたオブジェクト数 |
| `/First` | 整数 | **必須** | オブジェクトデータ領域の開始バイトオフセット（展開後データ内の位置） |
| `/Length` | 整数 | **必須** | ストリームデータのバイト長（ストリーム共通エントリ） |
| `/Filter` | 名前 or 配列 | 任意 | 圧縮フィルタ（通常 `/FlateDecode`）。省略時は未圧縮 |
| `/DecodeParms` | 辞書 or 配列 | 任意 | フィルタパラメータ（Predictor 等） |
| `/Extends` | 間接参照 | 任意 | 拡張元の親 ObjStm への間接参照 |

### 2-1. `/Filter` の例

```pdf
% 圧縮された ObjStm（一般的）
15 0 obj
<< /Type /ObjStm /N 3 /First 24 /Filter /FlateDecode /Length 200 >>
stream
... (zlib圧縮データ) ...
endstream
endobj

% 未圧縮の ObjStm（稀だが合法）
15 0 obj
<< /Type /ObjStm /N 2 /First 12 /Length 50 >>
stream
10 0 11 15 << /Key /Value >> true
endstream
endobj
```

## 3. 内部バイナリ構造

展開後のデータは、先頭 `/First` バイトの**オフセットテーブル領域**と、以降の**オブジェクトデータ領域**に分かれます。

```text
|<--- /First バイト --->|<--- オブジェクトデータ領域 --->|
|   オフセットテーブル     |   オブジェクト本体            |
```

### 3-1. オフセットテーブル領域

先頭 `/First` バイトに、`/N` 組の `(objNum, offset)` 整数ペアが空白区切りで並びます。`offset` は `/First` からの相対バイト位置です。

例: `/N 3`、`/First 24`、ヘッダ `"10 0 11 15 12 30"` の場合:

| インデックス | `objNum` | 相対 `offset` | 展開後データ内の開始位置 |
| :--- | :--- | :--- | :--- |
| `0` | `10` | `0` | `24 + 0 = 24` |
| `1` | `11` | `15` | `24 + 15 = 39` |
| `2` | `12` | `30` | `24 + 30 = 54` |

### 3-2. オブジェクトデータ領域

`/First` 以降に各オブジェクトの値が直接並びます。

- `obj` / `endobj` キーワードは**付かない**。
- 各オブジェクトの開始位置はオフセットテーブルで決定する。
- 辞書・配列・数値・文字列・名前・真偽値・`null` のいずれかが格納される。

```text
先頭 24 バイト: "10 0 11 15 12 30"              (オフセットテーブル)
24 バイト目〜:  << /Key1 /Value1 >>             (obj 10)
39 バイト目〜:  << /Key2 /Value2 >>             (obj 11)
54 バイト目〜:  true                            (obj 12)
```

## 4. 制約事項（ISO 32000-1:2008 §7.5.7）

### 4-1. ストリームオブジェクト格納不可

ストリームオブジェクト（`stream` / `endstream` を持つもの）は格納できません（`obj` / `endobj` 境界がないため）。

### 4-2. 世代番号は常に `0`

ObjStm 内オブジェクトの世代番号は常に `0` であり、非ゼロ世代のオブジェクトは格納できません。

### 4-3. ObjStm の入れ子禁止

ObjStm 自身もストリームであるため、4-1 により入れ子は自動的に禁止されます。

### 4-4. 暗号化

暗号化文書では、ObjStm 内の各オブジェクトを個別に暗号化せず、ObjStm のストリームデータ全体を 1 単位として暗号化します。

### 4-5. 格納不可オブジェクト

以下のオブジェクトは ObjStm に格納してはなりません。

- 暗号化辞書（`/Encrypt`）
- **ObjStm 自身の辞書**の `/Length` から間接参照されるオブジェクト（通常のコンテンツ/画像ストリームの `/Length` 参照先は対象外）
- xref から直接参照される必要があるオブジェクト（実装依存）

## 5. XRef との連携

### 5-1. XRef ストリームの `Type=2` エントリ（ISO 32000-1 §7.5.8）

| フィールド | 意味 | 例（obj 10 が ObjStm 15 の 0 番目） |
| :--- | :--- | :--- |
| Field1 (`type`) | `2`（圧縮オブジェクト） | `2` |
| Field2 | 親 ObjStm のオブジェクト番号 | `15` |
| Field3 | ストリーム内インデックス（0 起点） | `0` |

### 5-2. テキスト xref との関係

従来のテキスト形式 xref テーブルからは ObjStm 内オブジェクトを参照できません（XRef ストリーム、またはハイブリッド参照の `/XRefStm` が必要）。

---

## 6. `/Extends` による拡張

`/Extends` は別の ObjStm への間接参照で、ObjStm のコレクション（有向非巡回グラフ）を構成します（ISO 32000-1 §7.5.7 Table 16）。

```pdf
20 0 obj
<< /Type /ObjStm /N 1 /First 5 /Extends 15 0 R /Length 28 >>
stream
13 0 << /NewKey /NewValue >>
endstream
endobj
```

- **通常解決の原則**: xref の `Type=2` は実格納先 ObjStm の番号とインデックスを直接指定するため、通常解決に `/Extends` の探索は不要。
- **pdfmod の互換回復**: `/Extends` を持つコレクションについては、子から親への番号検索を互換回復として提供します（子に無ければ親を探索し、複数候補がある場合は子に最も近い値を採用）。`/Extends` が無い場合は xref インデックスとヘッダ番号の一致を厳格に検証します。

## 7. パース手順（概念的フロー）

1. XRef から `Type=2` エントリ（親 ObjStm 番号・インデックス）を取得する。
2. 親 ObjStm を通常の間接オブジェクトとして解決する。
3. ストリーム辞書（`/Type = /ObjStm`, `/N`, `/First`、および任意の `/Extends`）を検証する。`/Extends` がある場合は 7-2 の互換探索へ進む。
4. `/Filter` に従ってデータを展開する（`/FlateDecode` 等、省略時はそのまま）。
5. 先頭 `/First` バイトから、指定インデックスと次のインデックス（存在すれば）までの `(objNum, offset)` ペアを読み取る。
6. 指定インデックスの `objNum` が解決対象のオブジェクト番号と一致することを検証する。
7. `offset` と次エントリの `offset`（末尾なら本文終端）で境界を検証し、`/First + offset` からオブジェクトをパースする。

### 7-1. バイナリレイアウト図

```text
ObjStm ストリームデータ（展開後）
+------------------------------------------------------------------+
| オフセットテーブル (/First バイト)                                 |
| "10 0 11 15 12 30"                                               |
+------------------------------------------------------------------+
| /First + 0:   << /Type /Font /Subtype /Type1 >>     (obj 10)     |
| /First + 15:  << /Length 100 >>                     (obj 11)     |
| /First + 30:  true                                  (obj 12)     |
+------------------------------------------------------------------+
```

### 7-2. `/Extends` コレクションの互換探索（pdfmod の実装方針）

| 項目 | 仕様 |
| :--- | :--- |
| 探索と検証 | 各 ObjStm の全 `/N` ヘッダペアから対象番号を探し、最初に見つかった値を保持。発見後も終端まで親参照と辞書を検証（後続の親本文検索は省略）し、全リンク検証の成功後にキャッシュする |
| 親 ObjStm の要件 | xref `type=1` で実在し、参照の世代番号と一致する `/Type /ObjStm` ストリームであること（有効な非ゼロ世代も許容） |
| 循環・上限 | 訪問済み `(オブジェクト番号, 世代番号)` で循環検出。起点を含め**最大 64 件**を上限とし、64 件目に親がある場合は 65 件目を解決する前にエラー |
| エラーコード | 対象不在・親欠損・不正型/世代・循環・上限超過は `OBJECT_STREAM_INVALID`（親の解決失敗は元エラーのコードとメッセージを保持して包む）。本文・展開・ヘッダのエラーは既存コードを伝播 |

## 8. エッジケースと寛容処理

| ケース | PDF 仕様上の扱い | 推奨・pdfmod の処理 |
| :--- | :--- | :--- |
| `/First` や `/N` が不正（負値・実数・不在） | 不正な PDF | エラーを返す |
| オフセットテーブルのペア数が `/N` と不一致 | 不正な PDF | エラーを返す |
| 未圧縮 ObjStm（`/Filter` 省略） | 合法（稀） | 展開せずそのまま使用 |
| `/DecodeParms` 付き `/FlateDecode` | 合法（Predictor 逆変換が必要） | 対応するか非対応エラーを返す |
| ObjStm 内にストリームオブジェクトが存在 | 仕様違反 | エラーを返す |
| `/Extends` チェーンの循環 | 不正な PDF | 循環検出してエラーを返す |
| `/Extends` チェーンが 64 件超 | 規格上の固定上限なし | 安全上限としてエラーを返す |
| オフセットが展開後データ範囲外 | 不正な PDF | エラーを返す |
| ヘッダの `objNum` が XRef の番号と不一致 | 破損 PDF の可能性 | `/Extends` 無しならエラー、ありなら互換探索 |
