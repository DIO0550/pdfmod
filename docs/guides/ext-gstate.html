RESOURCES / GRAPHICS STATE

描画の設定を、
ひとつの名前で切り替える。

/GS1 gs は、リソース辞書にある設定を現在の描画状態へ適用します。線の太さも透明度も、以降の描画が使う同じ状態に入ります。

01　何をまとめる辞書か

グラフィックス状態は、これから描く線・文字・塗りの設定です。PDFは各図形に設定をすべて書き直すのではなく、命令を読んだ順に状態を更新します。たとえば 3 w を実行すると、以降の線の太さは3になります。

ExtGState（拡張グラフィックス状態）は、複数の設定をまとめた辞書です。gs は辞書の全体を別の状態として積む命令ではありません。辞書に書かれた項目だけを、現在の状態へ上書きします。

省略は「既定値へ戻す」ではない現在の線幅が5で、適用する辞書に /ca .4 だけがあれば、線幅5を保ったまま塗りの不透明度だけが0.4になります。

02　PDF記述を読む

以下はPDF全体ではなく、リソース辞書・間接オブジェクト・コンテンツストリームの抜粋です。

% ページのリソース辞書
/Resources <<
  /ExtGState << /GS1 10 0 R >>
>>

10 0 obj
<< /Type /ExtGState
   /LW 3 /CA 0.8 /ca 0.4
   /BM /Multiply
>>
endobj

% コンテンツストリーム
/GS1 gs
20 20 100 60 re
B

/GS1 は現在のリソース内だけで意味を持つ名前です。10 0 R はオブジェクト番号10・世代番号0への参照です。gs はこの名前を取り出し、/Resources → /ExtGState → /GS1 の順に辞書へ到達します。re は矩形のパスを作り、B は塗りと輪郭の描画を指示します。

/CA は輪郭の不透明度、/ca は塗りの不透明度です。大文字・小文字は区別されます。不透明度0は透明、1は不透明です。

03　パラメータと型

キーPDFの値現在の状態での役割
/LW数値線幅。w と同じ値を更新
/LC整数 0 / 1 / 2線端。順に平端・丸端・突出した四角端
/LJ整数 0 / 1 / 2線接合。順にマイター・丸・面取り
/ML数値マイター限界。M と同じ値を更新
/D[[2 3] 1]描画長2・空白長3を繰り返し、開始位置を1ずらす
/CA /ca0〜1輪郭／塗りの不透明度
/BM名前 または 名前の配列背景と描画色を混ぜる方式
/SMask辞書 または /None位置ごとの透明度を与えるマスク、または解除
/Font[font_ref size]フォント辞書とサイズ

ブレンドモードは、たとえば /Normal（通常）、/Multiply（乗算）、/Screen（スクリーン）です。配列 [/Future /Multiply /Screen] は優先順位を表し、最初に対応できるモードを使います。この実装では Multiply が選ばれます。対応できる名前のない配列は Normal になります。

状態の保持と、実際の描画は別この実装は透明度・ブレンドモード・ソフトマスクを状態として保持します。ピクセルの合成、透明グループの描画、ソフトマスク辞書の内部検証は実装範囲外です。線幅・マイター・破線の値域検証も既存の専用オペレータと同様に今後の範囲です。

04　フォント指定の違い

命令で指定する場合

/F1 12 Tf

F1 はリソースの /Font 内を引くための名前です。テキスト状態に名前・サイズと取得できた辞書を保持します。

拡張状態で指定する場合

/Font [6 0 R 12]

配列の先頭はフォント辞書への間接参照です。オブジェクト6を解決し、辞書とサイズ12を保持します。

TypeScriptの TextFont は、type によって2種類の指定を区別します。

type TextFont =
  | { readonly type: "name"; readonly name: string; readonly dictionary?: PdfDictionary }
  | { readonly type: "dictionary"; readonly dictionary: PdfDictionary };

どちらの指定も TextState.withFont を通り、現在のフォント指定を置き換えます。文字間隔や行送りは引き継ぎます。fontName は名前指定のときにその名前を返し、辞書指定では None を返します。

05　保存と復元

q は現在のグラフィックス状態を保存し、Q は直前に保存した状態を復元します。拡張状態も同じ状態に入るため、専用の「拡張状態スタック」は必要ありません。

5 w
q
  /GS1 gs   % LW=3, ca=0.4
  q
    9 w
  Q
Q
実行したところ現在の線幅塗りの不透明度
最初の 5 w51
/GS1 gs30.4
9 w90.4
内側の Q30.4
外側の Q51

06　警告と回復

以下は実行スコープを渡したときのpdfmodの回復方針です。

入力結果
<< /LW 3 /Unknown true /ca .4 >>未知キーを警告し、線幅3・不透明度0.4を適用
<< /CA 2 /LW 3 >>範囲外の不透明度を警告。以前の不透明度を保持し、線幅3を適用
/Missing gsEXT_GSTATE_NOT_FOUND。状態を保持して続行
選択した辞書や内部の参照先が構文エラーRESOURCES_RESOLVE_FAILED。原因を報告し、状態を保持して続行
未使用の名前の参照先が構文エラー取得結果に原因を保持。実行中の警告は追加しない

警告には gs 命令のバイト位置が付きます。同じ辞書を再度使うと、新しい命令位置で警告します。

07　実装の使い方

間接参照を非同期で解決し、コンテンツストリームは準備したスコープを使って同期で実行します。

const scope = await ContentStreamResources.fromResources(
  resources, resolveRef,
);
return ContentStreamInterpreter.execute({
  data: contentBytes,
  resources: scope,
});

各カテゴリ・名前の取得結果はスコープに保持されます。ページやフォームの辞書が変わるときは、その辞書を使って準備し直します。/OP や /RI など未対応の辞書キーは個別に警告します。/Type は辞書の種別として読み飛ばします。

このページの例は説明用です。PDF全体の読み込みや描画処理を実行するデモではありません。
