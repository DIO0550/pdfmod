PDFの日付文字列

PDF文書の情報辞書や注釈に記録される日時は、独自の日付文字列構文で表現されます。ISO 32000-1 / ISO 32000-2 の仕様規則、段階的省略、タイムゾーン形式、そして厳格なカレンダー検証の仕組みを解説します。

01

役割と全体像

PDFの日付は、(D:20261009143000+09'00') のようなリテラル文字列または16進文字列として、ドキュメントのメタデータ辞書（/CreationDate、/ModDate）や注釈・署名などに記録されます。

日付文字列 (Date String)

接頭辞 D: で始まり、年（4桁）を必須として月・日・時・分・秒・タイムゾーンが続く固定長ブロック形式の文字列表現です。

タイムゾーンオフセット (Offset)

UTCからの時差を表し、符号（+ / -）と時・分、またはUTCを表す Z で示されます。バージョンによってアポストロフィの区切り規則が異なります。

階層的省略と厳格検証年は必須であり、月以降は上位フィールドが存在する場合のみ順に省略できます。任意の位置でパースを打ち切るのではなく、グレゴリオ暦に準拠したうるう年や日・時・分・秒の有効範囲を厳格に検証します。
02

PDF記述を読む

次は文書情報辞書（Document Information Dictionary）における日付記述の抜粋です。

% 文書情報辞書の抜粋
<<
  /Title        (PDF Date Specification)
  /CreationDate (D:20261009143000+09'00')
  /ModDate      (D:20261009143500Z)
>>

構文要素の意味

D:
日付文字列であることを示す接頭辞（推奨ですが、接頭辞なしの文字列もパース対象として扱われます）。

YYYYMMDDHHmmSS
年（4桁）、月・日・時・分・秒（各2桁）。

+09'00' または Z
UTCからの時差。ISO 32000-1 形式では +HH'mm'、ISO 32000-2 形式では +HH'mm と末尾アポストロフィが省略されます。

アポストロフィ区切りの注意点PDFの日付構文では、時差の区切りとして +09'00' や +09'00 のようにアポストロフィ（'）が使用されます。一般的なISO 8601のコロン（+09:00）やアポストロフィなしの4桁（+0900）は構文エラーとなります。
03

仕様と取り扱い

PDF仕様（ISO 32000-1 / ISO 32000-2）における各構成要素の制約とパース規則です。

項目PDF仕様上の意味・範囲実装の取り扱い
D: 接頭辞日付を示す接頭辞存在すればスキップ。無くても年4桁から始まっていれば受理
YYYY（年）4桁の西暦（0000〜9999）必須項目。4桁の数字として数値化（i32）
MM（月）2桁の月（01〜12）省略可能。存在時は1〜12の範囲を検証
DD（日）2桁の日（01〜31）省略可能。うるう年判定を含む月の日数上限を検証
HH（時）2桁の時（00〜23）省略可能。0〜23の範囲を検証
mm（分）2桁の分（00〜59）省略可能。0〜59の範囲を検証
SS（秒）2桁の秒（00〜59）省略可能。0〜59の範囲を検証
タイムゾーン（TZ）+HH'mm' / -HH'mm' / +HH'mm / +HH' / +HH / Z秒までパース後、または月・日・時・分の各省略位置の直後に出現可能。不正形式は拒否
仕様と実装方針を区別するPDF仕様には不正な文字が含まれる場合の緩やかな回復規則の言及もありますが、本ライブラリではセキュリティと一貫性を重視し、余剰バイト（trailing garbage）や範囲外の日時は None として拒否する厳格パース方針を採用しています。
04

処理の流れを辿る

日付文字列バイト列のパース処理と状態遷移の流れです。

  1. 接頭辞と年の解析

    先頭の D: をスキップし、続く4バイトから年を数値化します。4桁未満や非数字の場合は無効と判定します。

  2. 段階的フィールドパース

    2桁ずつ読み進め、月（1〜12）、日（月ごとの日数・うるう年判定）、時（0〜23）、分（0〜59）、秒（0〜59）を順次決定します。途中でTZ開始文字に到達すればその時点で日付部のパースを打ち切ります。

  3. タイムゾーンの解析と構築

    Z（UTC）または +/- に続く時間・分のオフセット形式を解析し、余計な未消費バイトがないことを確認して PdfDate 構造体を生成します。

05

具体例で確かめる

仕様で認められる代表的な日付文字列と、エラーとなる入力例です。

TRY IT — 入力例を切り替える

完全な日付 (ISO 32000-1 / ISO 32000-2)

D:20261009143000+09'00'   % ISO 32000-1 (末尾アポストロフィあり)
D:20261009143000+09'00    % ISO 32000-2 (末尾アポストロフィなし)
D:20261009143000Z         % UTC 指定
すべての要素がパース成功年・月・日・時・分・秒およびタイムゾーンがそれぞれ Some(...) として格納されます。

省略とタイムゾーン

D:2026                    % 年のみ指定
D:202610+09'00'           % 月まで指定、以降省略してTZ
D:20261009143000+09'      % 分を省略（アポストロフィあり: +09'）
D:20261009143000+09       % 分を省略（アポストロフィなし: +09）
階層的な省略の受理上位のフィールドが存在していれば、下位のフィールド（秒や分、あるいは日以降すべて）が省略されても有効です。省略された項目は None となります。

不正な入力

D:20260229                % 平年の2月29日（うるう年不正）
D:20261301                % 13月（月の範囲外）
D:20261009143000+09:00    % コロン区切り（ISO 8601形式はPDF仕様外）
D:20261009143000+0900     % アポストロフィなし4桁TZ
D:20261009extra           % 末尾の余剰文字 (trailing garbage)
パース拒否 (None)カレンダーの不整合、非対応の区切り記号、余剰な未消費文字がある場合は安全のために None を返します。

説明用の例です。ブラウザ上でPDFパーサを実行するものではありません。

06

実装と対応範囲

Rustクレート pdfmod-core における PdfDate の利用例です。

use pdfmod_core::date::{PdfDate, PdfDateOffset, OffsetSign};

let raw = "D:20261009143000+09'00'";
let date = PdfDate::parse(raw).expect("valid PDF date");

assert_eq!(date.year(), 2026);
assert_eq!(date.month(), Some(10));
assert_eq!(date.day(), Some(9));
assert_eq!(date.hour(), Some(14));
assert_eq!(date.minute(), Some(30));
assert_eq!(date.second(), Some(0));

let offset = date.offset().expect("tz offset present");
assert_eq!(offset.sign(), Some(OffsetSign::Plus));
assert_eq!(offset.hours(), 9);
assert_eq!(offset.minutes(), 0);
assert_eq!(offset.total_offset_minutes(), 540);
assert!(matches!(offset, PdfDateOffset::Local(_)));
API・型役割・結果
PdfDate::parse(&str)UTF-8文字列からのパース。無効時は None
PdfDate::from_bytes(&[u8])PDFバイト列からのパース。無効時は None
PdfDateOffset::UtcUTC（Z）を表すバリアント（utc() でも生成可）
PdfDateOffset::Local(LocalOffset)検証済みローカル時差を保持するバリアント
PdfDateOffset::total_offset_minutes()符号を考慮した総オフセット分（-1439〜1439）を算出

今回対応する範囲

ISO 32000-1 / ISO 32000-2 日付構文のパース、段階的省略の受け入れ、カレンダー・うるう年検証、タイムゾーン形式の正規化。

後続処理・未対応の範囲

ローカルタイムへの日時計算、フォーマット出力・文字列化、情報辞書や注釈辞書からの自動取得。

覚えておくこと① 年は必須で、月以降は階層的に省略可能。② タイムゾーンは ' 区切りまたは Z。③ 平年の2月29日や余剰文字は厳格に拒否する。
