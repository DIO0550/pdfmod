PDF INTERNALS / DOCUMENT INFORMATION

ドキュメント情報辞書
/Infoを読む

PDFのタイトル・作成者・作成日時は、文書の末尾から辿れる辞書に入っています。 情報辞書の位置、文字列の読み方、そして一部の値が壊れていても他の項目を取得する仕組みを見ていきます。

01

文書についての情報を持つ辞書

ドキュメント情報辞書（Document Information Dictionary）は、タイトルや作成アプリケーションなどの付加情報を持つ辞書です。 トレイラ（Trailer）は文書の入口を示す辞書で、その/Infoが情報辞書への間接参照になります。

/Rootから文書構造へ

カタログとページツリーを辿って、ページの構造を読み取ります。詳しくはカタログの解説を参照してください。

/Infoから付加情報へ

タイトルや作成者などを取得します。Infoも各項目も省略でき、ページの解析を要求せずに情報辞書を取得できます。

CreatorとProducerの違いCreatorは元の文書を作ったアプリ、ProducerはPDFへ変換したアプリです。同じ値になる場合もあります。
02

トレイラから参照先を読む

次の記述はPDFの抜粋です。ヘッダ・xref・startxrefなどは省略しています。

% トレイラ内のInfoが5番のオブジェクトを指す
trailer
<< /Size 6 /Root 1 0 R /Info 5 0 R >>

5 0 obj
<< /Title (Sample PDF)
   /Author <FEFF65E5672C>
   /Subject (PDF Specification)
   /Keywords (pdf, metadata)
   /Creator (MyApp)
   /Producer (MyPDFLib 1.0)
   /CreationDate (D:20260314120000+09'00')
   /ModDate (D:20261013130000Z)
   /Trapped /False
   /VendorCode (ABC-123)
>>
endobj

5 0 Rはオブジェクト番号5・世代番号0への参照です。<< ... >>が辞書、 (...)がリテラル文字列、<...>が16進文字列を表します。 AuthorはUTF-16BEのBOM付きバイト列で、復元すると「日本」になります。

名前と真偽値は別の型/Trapped /Falseの値は名前オブジェクトです。 /Trapped falseは真偽値なので型エラーになります。
03

項目ごとに読む型が決まる

キー意味・型読み取り
Title / Author / Subject / Keywordsタイトル・作成者・主題・キーワード。テキスト文字列。PDFDocEncoding、BOM付きUTF-16BE・UTF-8を既存デコーダで復元。
Creator / Producer文書作成・PDF変換のアプリ名。テキスト文字列。上記と同じテキスト復元。
CreationDate / ModDate作成日時・更新日時。日付文字列。既存の日付パーサに生のバイト列を渡す。構文と日付の範囲を検証。
Trapped印刷時の色版のずれを補うトラッピング処理の状態。名前。True / False / Unknownの3値。省略はUnknown。未知の名前もUnknownに回復。
独自のキー作成アプリなどが付加する情報。解釈・参照解決せず元の辞書に保持。

日付例の+09'00'はUTCより9時間進む時差、ZはUTCを表します。 月以下の省略や時差の不在は日付パーサの表現を保ち、明示されていない成分を埋めません。

仕様の型とライブラリの回復方針テキストの不正な符号列はStrictで拒否します。未知のTrapped名はUnknownへ回復しますが、 名前以外の型や参照解決の失敗はエラーを保持します。文字列の置換や日付の自動修正は行いません。

エントリのnullは不在と同じ扱いです。一方、空の文字列()は存在する空テキストで、欠落とは区別します。 テキスト符号化の詳細はテキスト文字列の解説で確認できます。

04

辞書全体と項目の失敗を分ける

以下は取得処理の分岐です。情報辞書に到達できない失敗と、到達後の項目の失敗を区別します。

  1. Infoへの参照を解決する。

    辞書以外の値や解決不能なら、参照元トレイラの実ファイル位置を付けて返します。トレイラを持たないresolverではヘッダ位置付きのエラーです。

  2. 既知の9項目を個別に読む。

    項目の間接参照も解決します。1項目が失敗しても他の項目の読み取りを続けます。

  3. 解析結果と元の辞書を保持する。

    元の辞書をresolverと共有するので、未知のキーや壊れた文字列の元バイト列も取得できます。

05

正常・省略・不正を比較する

次の辞書は説明用の抜粋です。各結果はRust実装のテストで確認する挙動に対応しています。

正常な情報辞書

<< /Title (Annual Report)
   /CreationDate (D:20261013)
   /Trapped /True >>
値を型付きで取得Titleは「Annual Report」、CreationDateは2026年10月13日、TrappedはTrue。日付の時刻と時差は不在のままです。

一部欠落・未知の名前

<< /Title () /Author null
   /Trapped /Future /Custom 7 0 R >>
空テキスト・不在・回復を区別Titleは存在する空文字列、Authorは不在、TrappedはUnknown。 Customの参照はそのまま保持し、参照先が壊れていても読み込みません。Infoそのものがなければ空の結果です。

一部の値が壊れた辞書

<< /Title (intact)
   /Author <FEFFD800>
   /CreationDate (D:20260230)
   /ModDate (D:20261013)
   /Trapped true >>
3項目の失敗を保持し、正常値を取得Authorは孤立した上位サロゲート、CreationDateは存在しない2月30日、Trappedは名前以外の型です。 TitleとModDateは正常に取得できます。Authorのエラー位置2はBOMを含む文字列内のバイト位置で、PDFファイル位置ではありません。
06

取得APIと保持される結果

ObjectResolver::document_info()はResult<DocumentInfo, DocumentInfoError>を返します。 辞書を取得した後は、必要な項目のアクセサで成功・不在・エラーを分岐します。

let info = resolver.document_info()?;
match info.title() {
    Ok(Some(title)) => println!("{}", title.as_str()),
    Ok(None) => println!("タイトルはありません"),
    Err(error) => println!("タイトルを読めません: {error:?}"),
}
// Titleが失敗していても、Authorの結果は個別に取り出せる。
let author = info.author();
API返す内容
title() / author() / subject() / keywords() / creator() / producer()Result<Option<&PdfTextString>, &InfoValueError>
creation_date() / mod_date()Result<Option<&PdfDate>, &InfoValueError>
trapped()Result<Trapped, &InfoValueError>。不在・未知の名前はUnknown。
entry(key)既知・未知の元エントリ。参照や元のバイト列も変更しない。
object()元の辞書への借用。不在・NullならNone。

対応する範囲

9項目の解析、個別の失敗保持、項目の間接参照、オブジェクトストリーム内の情報辞書、未知キーの保持。

別の処理になるもの

情報辞書の編集・書き戻し、XMPメタデータの解析、暗号化文書の復号。現状のresolverは暗号化文書を開く際に拒否します。

情報の一部が壊れていても使える情報辞書の取得成功と、すべての項目の解析成功は別です。アクセサのResultを項目ごとに確認できます。
