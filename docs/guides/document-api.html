文書からページへ

PDFはオブジェクト同士の参照でできています。ファイルを開く処理、ページの属性を調べる処理、描画ストリームを読む処理を順にたどります。

01

文書の入口をつなぐ

相互参照情報（cross-reference / xref）は、間接オブジェクトの格納位置を示す索引です。トレイラ（trailer）の /Root が文書カタログ（Catalog）を指し、カタログの /Pages がページツリーの根を指します。

PdfDocument

ファイル構造とカタログを保持します。ページ・情報辞書・リソースを、必要になった操作ごとに解決する入口です。

PdfPage

対象ページの継承属性をまとめた結果です。元の辞書も保持するため、描画内容への参照を失いません。

開くことと、全部を読むことは別文書を開いた時点ではページを列挙しません。後続ページに壊れたオブジェクトがあっても、そこを読む操作まではエラーになりません。
02

PDF記述の参照関係

以下は説明用の抜粋です。ヘッダ・xref・トレイラ全体・各 endobj を省略しており、このままでは完全なPDFではありません。3 0 R は「オブジェクト番号3、世代番号0」への間接参照です。

trailer << /Root 1 0 R /Info 8 0 R ... >>
1 0 obj << /Type /Catalog /Pages 2 0 R >>
2 0 obj << /Type /Pages /Kids [3 0 R 4 0 R] /Count 2
           /MediaBox [0 0 600 800] /Resources 5 0 R /Rotate 90 >>
3 0 obj << /Type /Page /Parent 2 0 R /Contents 6 0 R >>
4 0 obj << /Type /Page /Parent 2 0 R /Contents [6 0 R 7 0 R] >>
5 0 obj << /Font << /F1 9 0 R >> >>
6 0 obj << /Length 1 >> stream ... endstream
7 0 obj << /Length 1 >> stream ... endstream
8 0 obj << /Title (Example) >>

ページの順序

/Kids の順に深さ優先でたどるため、最初は3番、次は4番です。オブジェクト番号の大小で並べ替えません。

継承の方向

ページから /Parent を根までたどります。両ページは親の600 × 800の矩形、90度回転、リソース辞書を継承します。

03

ページの属性と描画内容

項目意味・継承公開APIの取り扱い
MediaBox物理メディア矩形。継承可能。必須。対角を正規化し、寸法を取得できる。
CropBox表示矩形。継承可能。省略時はMediaBox。ここでは交差処理を適用しない。
Rotate時計回りの回転。継承可能。省略時0度。90度の倍数を0・90・180・270度へ正規化。
Resourcesフォントや画像の名前とオブジェクトを対応付ける辞書。継承可能。最も近い有効な辞書を取得。辞書内の参照先は読み込まない。
Contents描画命令のストリーム、またはその配列。継承しない。ページ固有の値を保持。明示操作でストリーム列へ解決。

継承属性の無効な局所値は警告として記録し、祖先を探すのが現在の回復方針です。親チェーンの欠落・循環や、有効なMediaBoxがどこにもない場合はエラーになります。Resourcesがどこにもない場合に空辞書を使うこともライブラリの回復方針です。

Contents配列は順序を保つ単一の 6 0 R も、[6 0 R 7 0 R] も受け取れます。配列を間接参照した形式にも対応します。PDFの処理では順に連結して命令を解釈しますが、この文書APIは展開・結合を行わず、ストリーム処理側へ渡す境界とします。

ストリームには /Filter が付くことがあり、生バイト列がそのまま描画命令とは限りません。各ストリームのフィルタを展開してから順序どおりに扱う必要があります。現在のRust文書APIは描画命令の解析までは提供しません。

04

必要になった段階で読む

操作読み込む範囲残すもの
open(bytes)ヘッダ、xref、トレイラ、カタログページツリー、Info、Resources、Contentsの参照先
page(index)先頭から対象までのツリー辞書、対象の親チェーンと継承属性後続ページ、リソース辞書内の参照先、Contents
page_count()初回はページツリー構造の全走査各ページの継承属性、リソース参照先、Contents
document_info()Info辞書とその項目ページ・描画内容
content_streams(page)指定ページのContents本体と各ストリームフィルタの展開、配列の結合、描画命令の解析

/Count は子孫の葉ページ数の宣言です。誤った宣言を使ってページを落とさないよう、現在の実装はCountで枝刈りしません。正確なページ数を得る操作は全辞書を走査しますが、文書を開く操作や先頭ページだけの取得に全走査を強制しません。

ページ取得のたびに先頭から対象までを走査します。間接オブジェクトの再利用には件数上限付きキャッシュを使いますが、ページ番号索引によるランダムアクセスの最適化は未実装です。

部分走査は全体の検証ではない先頭ページを取得できても、後続ノードが正しいとは限りません。祖先のCount不一致は枝を最後まで走査して退出したときに分かるため、途中で停止した走査では未検出です。構造全体を確かめるにはpage_countを呼びます。
05

正常・境界・エラー

正常：2ページの寸法を取得

先ほどの例では、最初のページも次のページも600 × 800、回転は90度です。2ページ目のContentsを読むと6番・7番のストリームが順番を保って返ります。フォント9番は必要になるまで解決されません。

境界：空・省略・範囲外

/Kids [] は現在の回復方針で0ページとして受理します。実ページ数が2なら、0起点のindex=2は Ok(None) です。Contentsの不在・Null・空配列は空のストリーム列になります。Infoが無ければタイトルなどは不在として取得できます。

回復：誤ったCount

Kidsに2ページあっても /Count 99 なら、page_countは2を返し、CountMismatch警告を保持します。Countの型不正や欠落も警告して走査を続けます。参照解決自体が失敗した場合はエラーです。

エラー：いつ検出するか

ヘッダ・xref・Rootの破損はopen時に検出します。後続ページの破損はその位置までの走査またはpage_countで検出します。Contents配列に整数・Null・配列が入っていたらcontent_streamsが配列位置付きのエラーを返します。Info項目の不正は他項目の成功を妨げません。

06

Rust APIで読む

use pdfmod_core::{DocumentError, PdfDocument, PageIndex};

fn inspect(bytes: &[u8]) -> Result<(), DocumentError> {
    let mut document = PdfDocument::open(bytes)?;
    if let Some(page) = document.page(PageIndex::from(0))? {
        let width = page.media_box().width();
        let rotation = page.rotation().degrees();
        let resources = page.resources();
        let streams = document.content_streams(&page)?;
    }
    let count = document.page_count()?;
    let info = document.document_info()?;
    Ok(())
}

入力バイト列は文書が借用します。PageIndexは0起点、PageNumberは1起点で0を構築できず、number.into() でPageIndexに変換します。PdfPageは読み取り専用の属性を持つため、次のページを取得しても前の結果を保持できます。

content_streams の結果は Vec<Rc<PdfObject>> で、各要素はStreamです。キャッシュされたオブジェクトを共有し、ストリームの大きな生バイト列を複製しません。page.contents() では解決前の値を確認できます。ページと参照は取得元の文書で使います。

暗号化文書の復号、Contentsの展開・連結・命令解析、描画、編集・書き出しはこの入口に追加していません。失敗はDocumentErrorの各段階で区別し、元の型付き原因を保持します。
