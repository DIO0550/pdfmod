ページの矩形を正しく読む

4つの数値から用紙と表示範囲を読み解きます。座標の正規化、5種類のボックスの既定値、交差の計算を具体例で確かめましょう。

対象：Rust pdfmod-core / Issue #636 実装版（本変更）

01

ページの「どこまで」を扱うのか

ページ境界ボックス（page boundary box）は、用紙・表示・印刷仕上げの範囲を表す矩形です。矩形（rectangle）は、軸に平行な四角形を対角の2点で指定します。

MediaBox：用紙の範囲

物理メディアの境界です。ページ自身、または親の Pages ノードから取得する必須の属性です。

CropBox：見せる範囲

表示・印刷する領域です。省略時は MediaBox が使われます。範囲外の描画内容を削除する操作ではありません。

座標の順序と、実際の領域を分けて考える2点の順序が逆でも同じ矩形です。読み取り時に各軸の最小値・最大値を求め、以後は正規化済みの型で扱います。
02

4つの数値から矩形を読む

次はページ辞書の抜粋です。完全なPDFではなく、参照先・描画内容などは省略しています。

<<
  /Type /Page
  /MediaBox [612 792 0 0]
  /CropBox [-10 20 620 780]
>>

[x₁ y₁ x₂ y₂]

/ から始まる名前が辞書キー、角括弧が配列です。最初の2数が一方の点、後半の2数がその対角の点です。整数と実数を混在させられます。

標準のユーザー空間ではXは右、Yは上へ増加します。UserUnit が既定値1なら1単位は1/72インチです。本APIは拡大や回転を適用しません。

min_x = min(x₁, x₂)     max_x = max(x₁, x₂)
min_y = min(y₁, y₂)     max_y = max(y₁, y₂)
幅 = max_x − min_x      高さ = max_y − min_y
03

5種類のボックスと既定値

キー意味省略時
MediaBox物理メディア継承先にもなければエラー
CropBox表示・印刷する範囲MediaBox
BleedBox制作時の裁ち落とし領域CropBox
TrimBox裁断後の仕上がり領域CropBox
ArtBox意味のあるコンテンツの領域CropBox

辞書内の null はキーの不在と同様に扱います。一方、型や配列の内容が不正な場合は、今回の検証APIではエラーを返します。

既定値は、ボックスの入れ子順序ではないBleedBox → TrimBox → ArtBox の順に既定値を引き継ぐわけではありません。3つとも直接 CropBox を参照します。明示された値は、それぞれ独立に MediaBox と交差させます。
04

はみ出した部分は交差で絞る

交差（intersection）は、2つの矩形の共通部分です。CropBox・BleedBox・TrimBox・ArtBox が MediaBox を超える場合、有効な領域を MediaBox との交差に縮めます。

  1. それぞれの矩形を正規化する。
  2. 左下は大きい方、右上は小さい方を採用する。
  3. 左下が右上を超えたら、共通部分なし。

    この状態を再び正規化すると、存在しない領域を作ってしまいます。APIでは None を返します。

辺や点で触れる場合等しい座標は許容し、幅・高さが0の矩形として保持します。離れている場合の None と区別します。これは本APIの表現方針です。
05

正常・境界・エラーを比べる

整数と実数の混在

[100.5 200 -10 0.25]

正規化後は [-10 0.25 100.5 200]。幅110.5、高さ199.75です。

面積0も保持

[5 10 5 20]

幅0、高さ10の矩形です。負の幅を作らず、そのまま扱えます。

入力・条件本APIの結果
[0 0 10] / [0 0 10 20 30]InvalidLength（要素数は正確に4）
[0 0 (10) 20]InvalidElement（index 2、String）
[0 0 10 0 R 20]InvalidElement（index 2、Reference）
MediaBox [0 0 100 200]
CropBox [110 10 120 20]		crop_box() は None。省略した3ボックスも None
同じ MediaBox、CropBox [100 20 110 30]幅0、高さ10の交差矩形
間接参照はPDF自体の禁止事項ではない10 0 R はオブジェクト番号10・世代番号0への参照です。配列やその要素の参照は、呼び出し側で解決してから渡します。今回の型が未解決参照を拒否することと、PDF仕様の妥当性は別です。

すべて静的な説明例です。ブラウザ上でRustパーサを実行しているわけではありません。

06

型の保証と呼び出し側の責務

API保証・責務
Rectangle::try_from(&PdfArray)4つの直接数値を検証し正規化。私有フィールドにより、外部から不変条件を破れない
width() / height()有限かつ非負の f64
intersection(&Rectangle)交差矩形、または共通部分なしの None
PageBoxes::from_dictionary(...)継承・参照解決済みの辞書を検証。既定値・MediaBoxとの交差を適用する準備
media_box()正規化済み MediaBox の借用
crop_box() / bleed_box() / trim_box() / art_box()既定値を適用した有効領域の Option<Rectangle>

この実装で検証すること

配列長・要素型・座標の有限性・幅と高さの有限性。不正な任意ボックスも黙って既定値には戻しません。

PageBoxError は対象キー、理由、呼び出し側が渡した位置を保持します。要素の index は0始まりで、ファイル中の位置そのものではありません。

後続の処理が担当すること

ページツリーの走査、MediaBox・CropBoxの継承、間接参照の解決、描画のクリッピング、Rotate・UserUnit の適用です。この変更ではまだ統合しません。

数値表現の実装上の制限座標は f64 です。大きな整数は f64 の精度で丸めます。NaN・無限大を含む手動構築オブジェクトと、差分が無限大になる極端な座標はエラーです。これらはライブラリの型保証のための制約です。
