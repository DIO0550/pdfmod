リソース辞書と属性継承

描画オペレータが参照するフォントや画像、色空間を名前と結びつける /Resources 辞書。ページツリーにおける「全置換原則」による継承ルールと、間接参照の2段階オンデマンド解決を解説します。

01

役割と全体像

PDF のコンテンツストリーム（描画命令列）では、フォントや画像、グラフィックス状態などの外部オブジェクトを /F1 12 Tf や /Im1 Do のようにリソース名で指定します。このリソース名と実際のオブジェクトを結びつけるのが Resources 辞書（/Resources） です。

/Resources 辞書

ページ（Page）またはページグループ（Pages）が保持する辞書です。カテゴリ名（/Font、/XObject など）をキーとし、その下に各リソース名の辞書をネストします。

属性の継承（全置換原則）

/Resources は親 Pages から子 Page へ継承される属性です。ただしキーごとのマージは行われず、最も近い先祖ノードの辞書で完全に置換（完全上書き）されます。

ここで押さえる要点 子ページに /Resources が定義されている場合、親 Pages のリソースは一切継承されません。また、リソース辞書内の間接参照はページ読み込み時に一括解決するのではなく、実際に必要となった時点で遅延（オンデマンド）解決します。
02

PDF記述を読む

次はページツリーとリソース辞書の関係を示す抜粋例です。

% 親 Pages ノード
2 0 obj
<<
  /Type /Pages
  /Kids [3 0 R]
  /Count 1
  /Resources <<
    /Font << /F1 10 0 R >>
    /XObject << /Im1 20 0 R >>
  >>
>>
endobj

% 子 Page ノード（リソース上書き）
3 0 obj
<<
  /Type /Page
  /Parent 2 0 R
  /Resources <<
    /Font << /F2 11 0 R >>
  >>
  /MediaBox [0 0 612 792]
>>
endobj

記号と値の意味

/Font << /F1 10 0 R >>
リソースカテゴリ /Font の下に、リソース名 /F1 とフォント辞書への間接参照 10 0 R が登録されています。

3 0 obj の /Resources
子 Page で /Font のみを持つリソース辞書が指定されています。この場合、親ノード（2 0 obj）に存在する /XObject（/Im1）は継承されず、子ページからは参照できません。

辞書のマージは行われません JavaScript のスプレッド構文やオブジェクトマージ（{ ...parent, ...child }）のような挙動を期待すると誤りになります。PDF仕様上、子辞書が存在する場合は親辞書全体が遮断されます。
03

仕様と取り扱い

ISO 32000-1 (PDF 1.7) Table 33 および ISO 32000-2 (PDF 2.0) Table 34 で定義されるリソースカテゴリと、本ライブラリでの取り扱いです。

カテゴリ名格納されるオブジェクト取り扱いと解決方針
Fontフォント辞書（Type 1, TrueType, Type 0 等）辞書オブジェクトまたはその間接参照を解決。
XObject外部オブジェクト（画像ストリーム、フォーム等）PdfStream または PdfDictionary を透過的に解決。
ExtGStateグラフィックス状態パラメータ辞書線幅、透明度、ブレンドモードなどの辞書を解決。
ColorSpace色空間辞書または名前・配列ICCBased、Separation、DeviceN などのオブジェクトを解決。
Patternタイリングパターンやシェーディングパターンパターンのストリームまたは辞書を解決。
Shadingスムーズシェーディング辞書グラデーション等のシェーディング辞書を解決。
Propertiesマークされたコンテンツのプロパティ辞書タグ付き PDF やレイヤー情報の辞書を解決。
ProcSetプロシージャセット（名前の配列）PDF 2.0 で非推奨。カテゴリとして扱わずスキップ。
未知のカテゴリ仕様外またはプライベートな辞書安全に保持され、同一の lookup API で取得可能。
仕様と実装方針を区別する PDF仕様ではカテゴリ辞書自体も間接参照（例: /Font 15 0 R）にすることが認められています。本実装では、カテゴリ辞書の間接参照と、その中に含まれる個別エントリの間接参照の両方をオンデマンドで解決する2段階解決（Two-stage lazy resolution）を採用しています。
04

処理の流れを辿る

ページツリー走査から個別リソースの取得までの全体フローです。

  1. ページツリーの属性継承探索

    対象ノード直下に /Resources があればそれを採用します。なければ祖先配列を葉から根に向かって順に走査し、最初に見つかった辞書を採用します。いずれにも無ければ PdfResources.createEmpty() を返します。

  2. 第1段階：カテゴリ辞書の解決

    lookup 時に、指定されたカテゴリ（例: Font）の値を取得します。直接辞書ならそのまま、間接参照なら resolveRef で辞書を解決します。

  3. 第2段階：個別エントリの解決

    カテゴリ辞書内から対象の名前（例: F1）のエントリを取り出します。直接値ならそのまま、間接参照なら resolveRef を呼び出してフォント辞書や画像ストリーム（PdfStream）を取得して返します。

05

具体例で確かめる

リソースの定義状況と lookup の解決結果のパターンです。

TRY IT — 入力例を切り替える

間接参照の連鎖解決

/Resources << /Font 2 0 R >>
2 0 obj << /F1 3 0 R >> endobj
3 0 obj << /Type /Font /Subtype /Type1 /BaseFont /Helvetica >> endobj
結果：Some(Helvetica Font Dict) が返る lookup(resources, "Font", "F1", resolveRef) により、まず 2 0 R が辞書として解決され、次に 3 0 R がフォント辞書として解決されて透過的に返されます。

全置換による上書き（親リソースの遮断）

親 Pages: /Resources << /Font << /F1 ... >> /XObject << /Im1 ... >> >>
子 Page : /Resources << /Font << /F2 ... >> >>
結果：F2 のみ取得可能、Im1 は ok(none) 子ページのリソース辞書が親を全置換するため、親に存在していた /XObject（/Im1）は参照できず、安全に none が返ります。

未定義・ProcSet・壊れた参照

/Resources <<
  /ProcSet [/PDF /Text]
  /Font << /F1 999 0 R >>
>>
% 999 0 R はファイル中に存在しない壊れた参照
結果：ProcSet は無視、未アクセスならエラーなし hasCategory("ProcSet") は false を返します。また、/F1 にアクセスしない限り壊れた 999 0 R の解決は走らないため、他エントリへのアクセスは阻害されません。

説明用の例です。ブラウザ上でPDFパーサを実行するものではありません。

06

実装と対応範囲

TypeScript API（@pdfmod/core）におけるリソースの利用例です。

import { PdfPage, PdfResources } from "@pdfmod/core";

// ページからリソース辞書を取得
const resources: PdfResources = page.resources;

// カテゴリ存在チェック（ProcSet は常に false）
if (PdfResources.hasCategory(resources, "Font")) {
  // フォントリソースの遅延解決
  const fontResult = await PdfResources.lookup(
    resources,
    "Font",
    "F1",
    resolveRef,
  );

  if (isOk(fontResult) && isSome(fontResult.value)) {
    const fontObj = fontResult.value.value;
    console.log("Found font:", fontObj);
  }
}
API・型役割・結果
PdfResources解決済みリソース辞書をラップする型。dictionary: PdfDictionary を保持。
PdfResources.createEmpty()リソース不在時のフォールバック用空辞書を生成。
PdfResources.from(dict?)辞書から PdfResources を安全に生成（引数なし時は空辞書）。
PdfResources.hasCategory(res, cat)カテゴリの存在判定。/ProcSet の場合は常に false。
PdfResources.getCategory(res, cat, resolveRef?)カテゴリ辞書を遅延解決して Option<PdfDictionary> を返却。
PdfResources.lookup(res, cat, name, resolveRef)カテゴリと個別エントリを2段階遅延解決して Option<PdfObject | PdfStream> を返却。

今回対応する範囲

ページツリーからの全置換属性継承、空辞書フォールバック、標準・カスタムカテゴリの保持、2段階オンデマンド解決、ストリーム透過返却、非推奨 /ProcSet の除外。

後続処理・未対応の範囲

フォント辞書内部のエンコーディング・CMAP 解析、画像ストリームのデコードとピクセル展開、コンテントストリーム描画命令の実行。

覚えておくこと ① /Resources はキー単位でマージされず、直近の祖先辞書で完全に上書きされます。② 間接参照はオンデマンド解決されるため、不要な解決オーバーヘッドや破損参照の巻き添えを防ぎます。③ PdfResources.lookup は辞書だけでなく画像などのストリームも透過的に返却します。
