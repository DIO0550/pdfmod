PDF INTERNALS / PAGE TREE

ページツリーと文書順

PDFのページは木構造に並びます。子の参照を順番に辿ると、ファイル内の配置やオブジェクト番号に左右されず、読む順番でページを取り出せます。

01

枝が Pages、葉が Page

ドキュメントカタログ（Document Catalog）の /Pages は、ページツリー（Page Tree）の根への間接参照です。/Pages ノードは子をまとめ、/Page ノードが1枚のページを表します。木の深さは一定ではありません。

/Kids：子の並び

直接の子への参照を並べた配列です。左から順に子へ降り、枝の中を最後まで読んでから次の兄弟へ進みます。これが深さ優先走査（Depth-First Search / DFS）です。

/Count：配下の葉の総数

直接の子の数ではありません。子の枝の下にあるページも数えます。下の根は Kids が2要素でも、Count は3です。

  1. 1ページ目：5 0 R
  2. 2ページ目：7 0 R
  3. 3ページ目：4 0 R
02

PDF記述を読む

上の図に対応する、説明用の抜粋です。ヘッダ・xref・トレイラ・ページ属性を省略しているため、完全なPDFではありません。

1 0 obj
<< /Type /Catalog /Pages 2 0 R >>
endobj
2 0 obj
<< /Type /Pages /Kids [3 0 R 4 0 R] /Count 3 >>
endobj
3 0 obj
<< /Type /Pages /Parent 2 0 R /Kids [5 0 R 6 0 R] /Count 2 >>
endobj
4 0 obj
<< /Type /Page /Parent 2 0 R >>
endobj
5 0 obj
<< /Type /Page /Parent 3 0 R >>
endobj
6 0 obj
<< /Type /Pages /Parent 3 0 R /Kids [7 0 R] /Count 1 >>
endobj
7 0 obj
<< /Type /Page /Parent 6 0 R >>
endobj

3 0 R は「オブジェクト番号3、世代番号0の間接参照（Indirect Reference）」です。/Type /Pages では Type がキー、Pages が名前オブジェクトの値です。カタログの /Pages 2 0 R は、Pages というキーに根への参照を設定しています。

ファイル内の位置とページ順は別4 の辞書が 5 より先に保存されていても、Kids を辿ると 5 → 7 → 4 になります。オブジェクト番号でソートしてはいけません。
03

仕様とライブラリの回復方針

PDF仕様では Type・Kids・Count は Pages の必須エントリです。欠落や矛盾をどう回復するかは、このライブラリが選んだ方針です。

入力走査の扱い
Type が /PagesKids を子参照の配列として検証し、文書順に辿る。
Type が /Page葉ページとして追加。根が Page なら RootIsPage エラー。
Type が欠落・null解決した Kids が非nullなら Pages と推定。Kids が欠落・nullなら、Parent が間接参照のとき Page と推定。InferredType 警告を返す。根にも同じ規則を適用。
Type に推定根拠がないCannotInferType エラー。空の辞書を無条件にページとして数えない。
Type が他の名前・不正な型InvalidType または InvalidKeyType エラー。明示された不正値を推定で上書きしない。
Count と実走査数が異なる各 Pages ノードについて CountMismatch 警告。実際に見つかったページ列を採用。
Count が欠落・null・負数・非整数MissingCount または InvalidCount 警告。Count による打ち切りや領域確保をしない。
Pages の Kids が欠落・null・非配列、要素が参照でない構造エラー。空配列 [] は走査上受理し、配下の葉数を0とする。
走査中の祖先を再訪ページツリーの循環として Cycle { node } エラー。戻った祖先のオブジェクト番号と世代番号を返す。
走査済みのノードを再訪循環ではない共有・重複として RepeatedNode { node } エラー。同じ親の Kids の重複も拒否。
参照解決失敗・参照先が辞書でないエラーを伝播。不正な子を黙って省略した部分ページ列は返さない。
Count の不一致をページ番号の根拠にしない枝の Count が0でも、Kids にページがあれば列挙します。ページ取得の範囲判定は実走査したページ数で行います。

Type・Kids・Count の値自体が間接参照なら、既存の resolver で参照チェーンを解決します。Kids の配列要素は子参照として保持し、走査時に解決します。参照チェーンの循環や深さ制限のエラーと、ページツリー自体の深さは別です。Count 参照の解決自体が失敗した場合も、下位の原因を保ったエラーになります。

04

明示スタックで深さ優先に辿る

明示スタック（Explicit Stack）は、次に行う作業をヒープ上の配列に積む方法です。関数を再帰呼び出しせず、ループで処理できます。

  1. 根への Enter 作業を積む

    作業を1つ取り出し、祖先集合を先に検査します。祖先なら Cycle、それ以外の訪問済みIDなら RepeatedNode。初訪問のノードだけ辞書を解決します。

  2. 葉ならページ列の末尾へ追加する

    元の辞書を共有して保持します。描画命令や属性の参照はここでは辿りません。

  3. 枝を祖先集合へ追加し、Leave と逆順の子の Enter を積む

    後入れ先出し（Last-In, First-Out / LIFO）なので、Kids が [3, 4] なら先に4、次に3を積みます。次に取り出す子は3です。

  4. Leave で祖先集合から除去し、枝の葉数を検証する

    Count が欠落・不正でも祖先集合からは除去します。枝へ入る前後のページ列の長さの差が、その枝の実際の葉数です。Count と比較して必要なら警告を記録します。

  5. スタックが空になったら結果を返す

    ページ列と警告を一緒に返します。木の走査には独自の深さ上限を設けず、1万階層でも同じループで処理します。

祖先集合：いま辿っている枝

Pages に入ると追加し、退出すると除去します。ここにあるIDへ戻れば、自己参照や途中の祖先への循環です。葉は子を辿らないので追加しません。

訪問済み集合：一度でも入ったノード

退出してもIDを保持します。祖先集合にはなく、こちらにあれば、別の枝からの共有や同じ親の重複です。番号と世代の組で区別します。

木の深さ上限を設けないのは、関数の再帰を使わず、深さに応じたコールスタックの消費を避けられるためです。有限の入力では、初訪問のノードだけを展開し、再訪をエラーにするので走査は終了します。正当な深い木を根拠のない上限で拒否しません。ただし、巨大な入力のメモリ使用量や処理時間に上限を保証する方針ではありません。

Parent は登るための逆参照文書順の列挙は Kids だけを辿ります。Parent の一致検証や、MediaBox・Resources などの継承は後続処理の担当です。
05

入力例を切り替えて確かめる

各例は説明用の辞書の抜粋です。操作は例の表示を切り替え、PDFパーサは実行しません。

単一ページ

2 0 obj << /Type /Pages /Kids [3 0 R] /Count 1 >> endobj
3 0 obj << /Type /Page /Parent 2 0 R >> endobj
1ページ、警告なしページ列は [3 0 R]。PageIndex(0) と PageNumber(1) が同じページを示します。

宣言が0でも子は辿る

2 0 obj << /Type /Pages /Kids [3 0 R 4 0 R] /Count 0 >> endobj
3 0 obj << /Type /Page /Parent 2 0 R >> endobj
4 0 obj << /Type /Page /Parent 2 0 R >> endobj
2ページ、CountMismatch 警告宣言値0、実走査数2。ページ列は [3 0 R, 4 0 R] を維持します。

構造から種別を推定する

2 0 obj << /Kids [3 0 R] /Count 1 >> endobj
3 0 obj << /Parent 2 0 R >> endobj
1ページ、InferredType 警告が2件2 は Kids があるため Pages、3 は Kids がなく Parent が参照のため Page。この回復はライブラリ独自の方針です。

空配列を安全に扱う

2 0 obj << /Type /Pages /Kids [] /Count 0 >> endobj
空のページ列PageIndex(0) の取得も None。Kids 自体が欠落した場合は MissingKids エラーになります。

子が根へ戻る

2 0 obj << /Type /Pages /Kids [3 0 R] /Count 1 >> endobj
3 0 obj << /Type /Pages /Kids [2 0 R] /Count 1 >> endobj
Cycle エラー、node は 2 02 → 3 → 2 と走査中の祖先へ戻ります。辞書自体の解決は成功しても、この親子関係の循環は別に検出します。ページ列は返しません。

循環しなくても木ではない

2 0 obj << /Type /Pages /Kids [3 0 R 4 0 R] /Count 2 >> endobj
3 0 obj << /Type /Pages /Parent 2 0 R /Kids [5 0 R] /Count 1 >> endobj
4 0 obj << /Type /Pages /Parent 2 0 R /Kids [5 0 R] /Count 1 >> endobj
5 0 obj << /Type /Page /Parent 3 0 R >> endobj

根の2から、3と4という別々の親が同じ5を指しています。有向非巡回グラフ（Directed Acyclic Graph / DAG）は、有向の循環を持たないグラフです。この例は DAG ですが、複数の経路が5へ合流するため木ではありません。5から3への Parent は Kids 走査では辿りません。

RepeatedNode エラー、node は 5 03の枝を退出した後、4の枝から5を再訪します。祖先ではないため循環とは区別します。PDFの木構造と単一の Parent に合わず、ページ番号や継承元が曖昧になるので、共有を受理せずページ列全体をエラーにします。枝を共有した場合も同じ方針です。

Kids の要素は子への間接参照

2 0 obj << /Type /Pages /Kids [3 0 R null] /Count 2 >> endobj
3 0 obj << /Type /Page /Parent 2 0 R >> endobj
InvalidKid エラー親の node は 2 0、0起点の index は1、actual は Null。子の辞書を直接置いた場合も参照ではないため拒否します。

要素が参照でも、参照先が未定義なら resolver は null を返し、子のIDを含む NotADictionary になります。構文や世代の不一致で解決に失敗した場合は Resolution と下位原因を返します。すでに正常なページを読めていても、部分的なページ列は成功として返しません。

06

ページ位置を型で区別する

PageIndex は0起点、PageNumber は1起点です。番号0は PageNumber にできません。文書に存在するかどうかは、走査済みの PageTree に問い合わせます。

取得済みの catalog を使う呼び出し側の抜粋です。走査失敗は PageTreeError として扱います。

let tree = resolver.page_tree(&catalog)?;
let first_index = PageIndex::from(0);
let first_page = tree.page(first_index);

let first_number = PageNumber::new(1); // Some
let invalid_number = PageNumber::new(0); // None
let out_of_range = tree.page(PageIndex::from(usize::MAX)); // None
// PageNumber は Into<PageIndex> で変換して取得する。
API・型役割
ObjectResolver::page_tree(&Catalog)根から走査。成功は PageTree、構造・解決失敗は PageTreeError。
PageTree::pages()文書順のページスライス。
PageTree::page(PageIndex)範囲内なら Some、範囲外なら None。
PageTree::warnings()各ノードの推定・Count 不正・不一致を型付きで報告。
Page::reference() / object()Kids の参照と元のページ辞書。参照値・未解釈エントリを保持。
PageIndex::number()1起点へ変換。usize::MAX の位置は番号を表現できず None。

対応する範囲

葉の列挙、間接参照の解決、Type の推定、各枝の Count 検証、循環・重複の検出、ページ位置の安全な取得。

後続処理の範囲

Parent の参照整合性、MediaBox・Resources・CropBox・Rotate の継承、コンテンツ解析、描画、ページ編集。明示的な Page の必須属性全体を検証するAPIではありません。
