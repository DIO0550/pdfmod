## 1. 概要

PDF ファイル解析の最下層は、入力バイトストリームをトークン列へ分割する**字句解析（レキシカルスキャナ）**です。PDF の構文は PostScript の影響を強く受けており、すべてのバイトを 3 種類に分類したうえで 9 種類の基本データ型を読み取ります。

## 2. バイト分類

ファイル内のすべてのバイトは、次の 3 種類に厳密に分類されます。

### 2.1 ホワイトスペース文字

トークンの区切りとして機能する 6 種類の制御・空白文字です。

| 文字コード | 名称 | 説明 |
| :--- | :--- | :--- |
| `0x00` | NUL | ヌル文字 |
| `0x09` | HT | 水平タブ |
| `0x0A` | LF | 改行（Line Feed） |
| `0x0C` | FF | フォームフィード |
| `0x0D` | CR | 復帰（Carriage Return） |
| `0x20` | SP | 空白（スペース） |

**パーサの要件**:

- 改行は **LF 単体**・**CR 単体**・**CR+LF** の 3 パターンすべてを等価に扱う。
- `CR+LF` のペアは **1 つの改行** として消費する（2 つの改行にしない）。
- ストリームデータ本体内のホワイトスペースは区切り文字ではなく、生データの一部として扱う。

### 2.2 デリミタ文字

トークンの境界と構造を示す 10 種類の特殊文字です。ホワイトスペースと同様に前後のトークンを区切ります。

| 文字 | 用途 |
| :--- | :--- |
| `(` `)` | リテラル文字列の開始・終了 |
| `<` `>` | 16 進文字列の開始・終了 / 二重（`<<` `>>`）で辞書の開始・終了 |
| `[` `]` | 配列の開始・終了 |
| `{` `}` | PostScript 関数（Type 4 関数など）で使用 |
| `/` | 名前オブジェクトの開始 |
| `%` | コメントの開始 |

### 2.3 通常の文字

ホワイトスペース文字・デリミタ文字のいずれにも該当しないバイトです。キーワードや数値などのトークンを構成します。

## 3. プリミティブデータ型

パーサはバイト列から次の **9 種類のプリミティブデータ型** を安全に構築できなければなりません。

### 3.1 Nullオブジェクト

```pdf
null
```

- 値が存在しないことを示すキーワード。
- 辞書エントリの値が `null` の場合、そのキーが存在しないのと同じ扱いになる（継承されたエントリの明示的クリアなどにも使われる）。
- 解決できない間接参照の結果としても返される。

| 項目 | 仕様 |
| :--- | :--- |
| 等値性 | 単一値（すべての `null` は等価） |
| シリアライズ | `null`（4 バイト固定） |

### 3.2 ブール値

```pdf
true
false
```

- 論理値を表すキーワードで、主にフラグ制御に使う。
- 大文字・小文字を区別する（`True` や `FALSE` は無効）。

| 項目 | 仕様 |
| :--- | :--- |
| 取りうる値 | `true` / `false` の 2 値 |
| シリアライズ | `true`（4 バイト） / `false`（5 バイト） |

### 3.3 数値（整数・実数）

```pdf
% 整数の例
123  -45  0  +17

% 実数の例
34.5  -3.62  +123.6  .002  4.  -.002
```

#### 構文ルールと制約

| 項目 | 仕様 |
| :--- | :--- |
| 符号 | 先頭の `+`（正）・`-`（負）を許容する |
| 小数点 | `.002` や `4.` は有効。`.` 単独や連続する `..` は無効 |
| 指数表記 | **仕様上禁止**（例: `1.23e4`）。厳格モードではエラー、寛容モードでは実世界の PDF 対応として許容する場合がある |
| 推奨範囲・精度 | 整数は最低でも 32 ビット符号付き整数（実装上は 64 ビット符号付き整数や安全整数を推奨）、実数は IEEE 754 倍精度浮動小数点数を推奨 |

### 3.4 リテラル文字列

丸括弧 `(` `)` で囲まれたバイト列です。

```pdf
(Hello World)
(Strings may contain newlines
and such.)
(Strings may contain balanced parentheses () and
special characters (*!&}^% and so on).)
(The following is an empty string.)
()
```

#### エスケープシーケンス

| シーケンス | 意味 |
| :--- | :--- |
| `\n` | 改行（LF: `0x0A`） |
| `\r` | 復帰（CR: `0x0D`） |
| `\t` | 水平タブ（HT: `0x09`） |
| `\b` | バックスペース（BS: `0x08`） |
| `\f` | フォームフィード（FF: `0x0C`） |
| `\(` | 左括弧 |
| `\)` | 右括弧 |
| `\\` | バックスラッシュ |
| `\ddd` | 8 進数表記の文字（`d` は `0`〜`7`、1〜3 桁。上位オーバーフローは無視） |

#### パーサの要件

- **括弧のネスト追跡**: `(` と `)` がバランスしていればエスケープなしで含められるため、パーサは括弧のネスト深度を追跡する。
- **行継続**: 行末の `\` と直後の改行（LF / CR / CR+LF）は無視され、文字列に含めない。
- **未定義エスケープ**: `\` の直後に上記以外の文字が続く場合、`\` だけを無視して後続文字をそのまま含める。
- **内部表現**: 文字コードではなく生のバイト列として保持する（テキストとしての解釈は PDFDocEncoding / UTF-16BE / UTF-8 や `/ToUnicode` に委ねる）。

### 3.5 16進文字列

山括弧 `<` `>` で囲まれた 16 進表現のバイト列です。

```pdf
<48656C6C6F>             % => "Hello"
<48656C6C6F20576F726C64> % => "Hello World"
<901FA3>                 % => 3バイトのバイナリデータ
<901FA>                  % => <901FA0> として解釈（末尾に 0 を補完）
```

#### パーサの要件

- 2 文字の 16 進数字ペアを 1 バイトへ変換する。
- 大文字・小文字を区別しない（`a`〜`f` と `A`〜`F` は等価）。
- 16 進数字の間のホワイトスペースは無視する。
- **奇数桁の末尾補完**: 桁数が奇数の場合、末尾に `0` を補ったものとして解釈する（例: `<ABC>` → `<ABC0>`）。

### 3.6 名前（Name）オブジェクト

`/` で始まるアトミックなシンボルです。文字列とは異なり、主に辞書のキーや列挙値として使われます。

```pdf
/Type
/Subtype
/Hello#20World             % => "Hello World"（スペースを含む名前）
/paired#28#29parentheses   % => "paired()parentheses"
/A#42                      % => "AB"
```

#### 構文ルール

- `/` の直後から、次のホワイトスペースまたはデリミタの手前までが名前の範囲となる。
- 大文字・小文字を**区別する**（`/Type` と `/type` は別の名前）。
- `#` の後ろに 2 桁の 16 進数字を置くことで任意のバイトを表現できる。
- 名前の最大長に仕様上の厳密な上限はないが、127 バイトが推奨上限とされている。
- 比較・ハッシュはデコード後のバイト列の完全一致で行う。

#### pdfmod の実装方針（`#` エスケープと `#00` の扱い）

ISO 32000-1 では名前中のヌル文字（`0x00`）は明示禁止されていませんが、ISO 32000-2 §7.3.5 では禁止されています。pdfmod では次の規則で読み取り、名前トークン自体が構文エラーで失敗しないようにします。

| パターン | 例 | 解釈結果 | 理由 |
| :--- | :--- | :--- | :--- |
| `#` + 16 進 2 桁（`0x01`〜`0xFF`） | `/A#42` | `AB`（デコード） | 正常なエスケープ |
| `#00`（デコード結果が `0x00`） | `/A#00B` | `A#00B`（`#` をリテラル扱い） | ISO 32000-2 §7.3.5 の NUL 禁止に準拠 |
| 入力末尾で 2 文字足りない | `/A#`, `/A#4` | `A#`, `A#4`（`#` をリテラル扱い） | 寛容に読み取りを継続 |
| 16 進数字以外を含む | `/A#zz`, `/A#4z` | `A#zz`, `A#4z`（`#` をリテラル扱い） | 寛容に読み取りを継続 |

### 3.7 配列（Array）

角括弧 `[` `]` で囲まれた順序付きのオブジェクトリストです。

```pdf
[549 3.14 false (Ralph) /SomeName]
```

- 要素間の区切り記号は不要（ホワイトスペースまたはデリミタで区切る）。
- 異なるデータ型を混在でき、任意の深さでネスト可能。
- 空配列 `[]` も有効。
- 0 始まりのインデックスで要素へアクセスする。

### 3.8 辞書（Dictionary）

二重山括弧 `<<` `>>` で囲まれた、キーと値のペアの集合です。PDF において最も重要なデータ構造です。

```pdf
<< /Type /Example
   /Subtype /DictionaryExample
   /Version 0.01
   /IntegerItem 12
   /StringItem (a string)
   /Subdictionary << /Item1 0.4
                     /Item2 true
                     /LastItem (not!)
                  >>
>>
```

#### 制約と推奨事項

- **キーは必ず名前（Name）オブジェクト**でなければならない。
- 値には配列や入れ子の辞書を含む任意のデータ型を指定できる。
- 同一キーが重複した場合の動作は仕様上未定義（後勝ちで最後の値を採用する実装が多い）。
- 書き出し時の出力を安定させるため、実装上は順序を保持できるマップ構造（挿入順またはキー順）の利用が望ましい。

### 3.9 ストリーム（Stream）

メタデータを表す辞書と、それに続く任意のバイナリデータ本体からなる複合オブジェクトです。ストリームは必ず間接オブジェクトとして定義されます。

```pdf
<< /Length 44 >>
stream
BT
/F1 24 Tf
72 720 Td
(Hello World) Tj
ET
endstream
```

#### 構成要素

1. **辞書部分**: 長さや圧縮フィルタなどのメタデータを定義する。
2. **`stream` キーワード**: データ本体の開始を示す。直後に **CR+LF** または **LF** が必須（CR 単体は不可）。
3. **バイナリデータ**: `/Length` で指定された長さの生バイト列。
4. **`endstream` キーワード**: データ本体の終了を示す。直前に EOL を置くことが推奨される。

#### 必須・オプションの辞書エントリ

| キー | 必須 | 型 | 説明 |
| :--- | :--- | :--- | :--- |
| `/Length` | **必須** | 整数 | ストリームデータの**正確なバイト数**（`stream` 直後の EOL の次から `endstream` 直前の EOL の手前まで）。間接参照も可 |
| `/Filter` | 任意 | 名前 or 配列 | 適用されている圧縮・エンコードフィルタ（[07章](./07_compression_filters.md)） |
| `/DecodeParms` | 任意 | 辞書 or 配列 | フィルタ固有のデコードパラメータ |
| `/DL` | 任意 | 整数 | デコード後のデータ長（ヒント情報） |

## 4. ダイレクトオブジェクトとインダイレクトオブジェクト

### 4.1 ダイレクトオブジェクト

配列や辞書の中にインラインで直接記述されるオブジェクトです。

```pdf
[1 2 3]                % 配列内のダイレクトオブジェクト
<< /Key (value) >>     % 辞書内のダイレクトオブジェクト
```

### 4.2 インダイレクト（間接）オブジェクト

一意の識別子を持ち、ファイル内の任意の場所から参照できるオブジェクトです。

#### 定義構文と参照構文

```pdf
% 定義構文
<オブジェクト番号> <世代番号> obj
  <オブジェクト本体>
endobj

% 参照構文（インダイレクト参照）
<オブジェクト番号> <世代番号> R
```

#### 具体例

```pdf
% オブジェクト番号 12、世代番号 0 のページ辞書定義
12 0 obj
<< /Type /Page
   /Contents 15 0 R    % オブジェクト 15、世代 0 への参照
>>
endobj

% オブジェクト番号 15、世代番号 0 のストリーム定義
15 0 obj
<< /Length 44 >>
stream
BT /F1 24 Tf 72 720 Td (Hello) Tj ET
endstream
endobj
```

### 4.3 間接参照のメカニズム

- `N G R` は「オブジェクト番号 `N`、世代番号 `G` のオブジェクトをここで参照する」というポインタとして機能する。
- フォントや画像などの重いデータを複数ページで共有し、重複を排除できる。
- 参照先が存在しない（または削除済みである）場合は `null` として解決される（詳細は [02a章](./02a_object_resolution.md)）。

### 4.4 オブジェクト識別子の構成

間接オブジェクトは `(オブジェクト番号, 世代番号)` のペアで一意に識別されます。比較やハッシュもこの 2 要素の組で行います。

| 要素 | 仕様上の範囲 | 説明 |
| :--- | :--- | :--- |
| オブジェクト番号 | 正の整数（1 以上） | ファイル内でオブジェクトを一意に識別する番号（ISO 32000-1 §7.3.10） |
| 世代番号 | 非負整数（0〜65535） | 通常は `0`。オブジェクトが削除・再利用されるたびにインクリメントされる |

#### pdfmod の実装方針（`ObjectNumber` と `FreeObjectNumber` の分離）

ISO 32000-1 §7.3.10 が「positive integer object number」と規定するとおり、番号 `0` は実在オブジェクトを指しません。`0` は §7.5.4 の空きオブジェクト連結リストで予約された特殊な値です。

| 型名（TS / Rust 共通） | 表現できる値 | 用途 |
| :--- | :--- | :--- |
| `ObjectNumber` | **1 以上**（`0` を表現できない） | 間接オブジェクト定義、間接参照、xref テーブルのキー |
| `FreeObjectNumber` | **0 以上**（`0` を許容） | xref の空き（free）エントリが指す「次の空きオブジェクト番号」リンク値 |

### 4.5 キャッシュ戦略

- 解決済みの間接参照はキャッシュして重複パースを避ける。
- 巨大な PDF でのメモリ枯渇を防ぐため、LRU（Least Recently Used）キャッシュの利用を推奨する。
- 破損・悪意ある PDF での無限ループを防ぐため、訪問済みオブジェクト ID の追跡による循環参照検出を必ず実装する（詳細は [02a章 §6](./02a_object_resolution.md#6-循環参照)）。

## 5. コメント

```pdf
% これはコメントです（行末まで有効）
%PDF-1.7                         % ファイルヘッダ（特殊なコメント）
%%EOF                            % ファイル終端マーカー（特殊なコメント）
```

- `%` から行末までがコメントとして扱われる。
- 通常のコメントはトークンにならず、ホワイトスペースと同等に無視される。
- **例外**: ファイル先頭の `%PDF-` とファイル末尾の `%%EOF` は構造上特別な意味を持つ。
- ストリームデータ本体内の `%` はバイナリデータの一部であり、コメントとしては解釈されない。
