# 02b. 暗号化 (Encryption)

ISO 32000-1:2008 §7.6 / ISO 32000-2:2020 §7.6

> 本書は**暗号化辞書の構造**のみを扱う。復号アルゴリズム（RC4 / AES）・鍵導出・
> パスワード認証は未記載（#604 のスコープ外）。

## 1. 暗号化辞書の位置づけ

暗号化された PDF では、トレイラの `/Encrypt` が暗号化辞書を指す（[02_file_structure.md](./02_file_structure.md) §5.3）。この辞書は「どのセキュリティハンドラが、どのアルゴリズムで、どのオブジェクトを暗号化しているか」を記述する。

- `/Encrypt` の値は**間接参照でも直接辞書でも**書ける
- 暗号化辞書自体はオブジェクトストリームに格納できない（暗号化の起点であり、復号前に読める必要があるため）
- 暗号化された文書ではトレイラの `/ID` が必須（鍵導出の入力になる）
- 暗号化の対象は文字列とストリームであり、辞書のキー名・数値・名前オブジェクトは暗号化されない

セキュリティハンドラは `/Filter` で識別する。ISO が定義するのは**標準セキュリティハンドラ** `/Standard`（パスワードベース）で、公開鍵ベースの `/Adobe.PubSec` などはハンドラ固有の追加キー（`/Recipients` など）を持つ。

## 2. 標準セキュリティハンドラのキー

ISO 32000-1 表 20（共通）・表 21（標準ハンドラ）。

| キー | 型 | 必須 | 既定値 | 意味 |
|:-----|:---|:-----|:-------|:-----|
| `/Filter` | 名前 | **必須** | — | セキュリティハンドラ名。標準は `/Standard` |
| `/SubFilter` | 名前 | 任意 | — | ハンドラ固有のサブ形式（公開鍵ハンドラなどで使用） |
| `/V` | 整数 | **必須** | — | アルゴリズム版（§3）。ISO は既定値 0（未文書化アルゴリズム）を定めるが、本実装は欠落を構造不正として扱う |
| `/R` | 整数 | **必須** | — | リビジョン（§3） |
| `/Length` | 整数 | 任意 | 40 | ファイル暗号鍵の長さ（ビット）。40..=128 かつ 8 の倍数 |
| `/O` | 文字列 | **必須** | — | 所有者パスワードから導出した値（R2-4 は 32 バイト、R5/R6 は 48 バイト） |
| `/U` | 文字列 | **必須** | — | 利用者パスワードから導出した値（長さは `/O` と同じ） |
| `/OE` | 文字列 | R5/R6 で必須 | — | 所有者用の暗号化ファイル鍵（32 バイト） |
| `/UE` | 文字列 | R5/R6 で必須 | — | 利用者用の暗号化ファイル鍵（32 バイト） |
| `/P` | 整数 | **必須** | — | アクセス権限フラグ。符号付き 32 ビット（§5） |
| `/Perms` | 文字列 | R5/R6 で必須 | — | 権限の暗号化コピー（16 バイト） |
| `/EncryptMetadata` | 真偽値 | 任意 | true | 文書メタデータを暗号化するか（`/V 4` 以降） |
| `/CF` `/StmF` `/StrF` `/EFF` | — | `/V 4` 以降 | — | crypt filter（§4） |

## 3. `/V` と `/R` の組み合わせ

`/V` はアルゴリズム版、`/R` はハンドラのリビジョンで、両者の組み合わせは仕様上 6 種に限られる。

```
   /V \ /R │  2        3        4        5        6      その他
  ─────────┼────────────────────────────────────────────────────
      0    │  ✗        ✗        ✗        ✗        ✗        ✗     ← 未文書化アルゴリズム
      1    │ V1R2     V1R3      ✗        ✗        ✗        ✗
      2    │  ✗       V2R3      ✗        ✗        ✗        ✗
      3    │  ✗        ✗        ✗        ✗        ✗        ✗     ← 非公開アルゴリズム
      4    │  ✗        ✗       V4R4      ✗        ✗        ✗
      5    │  ✗        ✗        ✗       V5R5     V5R6      ✗
    その他  │  ✗        ✗        ✗        ✗        ✗        ✗
```

| 組み合わせ | 暗号方式 | 鍵長 | 備考 |
|:-----------|:---------|:-----|:-----|
| `/V 1` `/R 2` | RC4 | 40 ビット固定 | 最初期の暗号化 |
| `/V 1` `/R 3` | RC4 | 40 ビット固定 | リビジョン 3 固有の権限ビットを使う場合 |
| `/V 2` `/R 3` | RC4 | `/Length`（40..=128） | 可変長 RC4 |
| `/V 4` `/R 4` | crypt filter で選択 | `/Length` | `/CF` で方式を指定（AES-128 など） |
| `/V 5` `/R 5` | AES-256 | 256 ビット固定 | Adobe ExtensionLevel 3。ISO 32000-2 で非推奨 |
| `/V 5` `/R 6` | AES-256 | 256 ビット固定 | ISO 32000-2 §7.6.4.3 |

`/V 0` は未文書化のアルゴリズム、`/V 3` は非公開のアルゴリズムを表し、いずれも内容が規定されていない。

## 4. crypt filter

`/V 4` 以降では、暗号方式を暗号化辞書直下ではなく **crypt filter** で指定する。

| キー | 型 | 意味 |
|:-----|:---|:-----|
| `/CF` | 辞書 | crypt filter 名 → crypt filter 辞書の対応表 |
| `/StmF` | 名前 | ストリームに適用する crypt filter 名。既定 `/Identity` |
| `/StrF` | 名前 | 文字列に適用する crypt filter 名。既定 `/Identity` |
| `/EFF` | 名前 | 埋め込みファイルストリームに適用する crypt filter 名 |

`/CF` の各エントリ（ISO 32000-1 表 25）:

| キー | 型 | 既定値 | 意味 |
|:-----|:---|:-------|:-----|
| `/CFM` | 名前 | `/None` | 暗号方式。`/None` / `/V2`（RC4）/ `/AESV2`（AES-128）/ `/AESV3`（AES-256） |
| `/AuthEvent` | 名前 | `/DocOpen` | 認証イベント。`/DocOpen` / `/EFOpen` |
| `/Length` | 整数 | — | 鍵長。ISO はバイト単位と規定するが、ビット単位で書く実装も存在する。本実装は 5..=16 をバイト表記とみなして 8 倍し、それ以外はビット表記としてそのまま扱ったうえで、40..=128 かつ 8 の倍数のみを受理する（両表記の定義域は重ならないため一意に決まる）。解釈できない値はエラーにせず無視する |

`/Identity` は `/CF` に定義されない**組み込みの名前**で、「暗号化しない」を意味する。`/StmF` `/StrF` `/EFF` が `/Identity` 以外の名前を指す場合、その名前は `/CF` に定義されていなければならない。

## 5. アクセス権限フラグ `/P`

`/P` は符号付き 32 ビット整数のビットフラグ（ISO 32000-1 表 22）。ビット位置は 1 起点で数え、値が 1 のとき**許可**、0 のとき禁止を表す。ビット 1-2 と 7-8 は予約（常に 1）。

| ビット | 意味 |
|:-------|:-----|
| 3 | 印刷（`/R 3` 以上では低解像度印刷） |
| 4 | 内容の変更 |
| 5 | テキスト・グラフィックスの抽出 |
| 6 | 注釈の追加・変更、フォームフィールドの記入 |
| 9 | フォームフィールドの記入（`/R 3` 以上） |
| 10 | アクセシビリティ目的の抽出（ISO 32000-2 で非推奨） |
| 11 | 文書の組み立て（ページの挿入・回転・削除） |
| 12 | 高解像度での印刷（`/R 3` 以上） |

実在の PDF には `/P` を符号なし表記（例: `4294967292` = `-4` と同じビットパターン）で書くものがある。

## 6. pdfmod での扱い

- 暗号化辞書は `crate::encrypt::EncryptDictionary` として型化する（#604）
- `/V` × `/R` は §3 の 6 種だけを `StandardAlgorithm` のバリアントとして持ち、不正な組み合わせを構築できないようにする
- 未対応のセキュリティハンドラ（`/Adobe.PubSec` など）・未対応の `/V` は `EncryptDictionary::Unsupported` として生の辞書を保持し、**解析を止めない**
- `/Filter` `/V` `/R` の欠落や、Standard と名乗る辞書の構造不正は `EncryptError` として位置情報付きで報告する
- `/O` `/U` `/OE` `/UE` `/Perms` は長さを検証せずバイト列のまま保持する（検証は鍵導出の実装の責務）
- 暗号化辞書の中に書かれた間接参照（`/Length 5 0 R` など）は解決しない
- 復号処理（RC4 / AES）・鍵導出・パスワード認証は未実装
