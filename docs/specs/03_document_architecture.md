## 1. 概要

PDF の論理構造は、**ドキュメントカタログ（Document Catalog）を頂点とする有向非巡回グラフ（DAG）**として表現されます。物理ファイルの相互参照テーブル（[02章](./02_file_structure.md)）とオブジェクト解決（[02a章](./02a_object_resolution.md)）が整うと、トレイラの `/Root` からこの論理構造を辿ってページやメタデータへアクセスできます。

## 2. ドキュメントカタログ

トレイラ辞書の `/Root` エントリから参照される、ドキュメント全体のルート辞書です。

### 2.1 カタログ辞書の構造

```pdf
1 0 obj
<< /Type /Catalog
   /Pages 2 0 R
   /Version /1.7
   /ViewerPreferences << /DisplayDocTitle true >>
   /Outlines 10 0 R
   /Names 20 0 R
   /MarkInfo << /Marked true >>
   /Lang (ja-JP)
>>
endobj
```

### 2.2 カタログ辞書の主要エントリ

| キー | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| `/Type` | 名前 | **必須** | 必ず `/Catalog` |
| `/Pages` | 間接参照 | **必須** | ページツリーのルートノードへの参照 |
| `/Version` | 名前 | 任意 | ファイルヘッダのバージョンを上書きする場合に指定（[02章 §2.2](./02_file_structure.md#22-バージョンの上書きルール)） |
| `/ViewerPreferences` | 辞書 | 任意 | ビューアの表示設定 |
| `/Outlines` | 間接参照 | 任意 | アウトライン（しおり/ブックマーク）のルート |
| `/Names` | 辞書 | 任意 | 名前辞書（名前付き宛先など） |
| `/Dests` | 辞書 | 任意 | 名前付き宛先辞書（PDF 1.1 互換） |
| `/MarkInfo` | 辞書 | 任意 | タグ付き PDF（アクセシビリティ）の情報 |
| `/StructTreeRoot` | 辞書 | 任意 | 構造ツリーのルート（タグ付き PDF） |
| `/Lang` | 文字列 | 任意 | ドキュメントの自然言語（BCP 47 形式） |
| `/PageLayout` | 名前 | 任意 | ページレイアウトモード（§2.3） |
| `/PageMode` | 名前 | 任意 | 表示モード（§2.4） |
| `/AcroForm` | 辞書 | 任意 | インタラクティブフォームの定義 |
| `/Metadata` | ストリーム | 任意 | XMP メタデータストリーム |

### 2.3 PageLayout の値

| 値 | 説明 |
| :--- | :--- |
| `/SinglePage` | 1 ページずつ表示（既定値） |
| `/OneColumn` | 単一列の連続スクロール |
| `/TwoColumnLeft` | 2 列表示（奇数ページが左） |
| `/TwoColumnRight` | 2 列表示（奇数ページが右） |
| `/TwoPageLeft` | 見開き表示（奇数ページが左） |
| `/TwoPageRight` | 見開き表示（奇数ページが右） |

### 2.4 PageMode の値

| 値 | 説明 |
| :--- | :--- |
| `/UseNone` | アウトラインパネルもサムネイルパネルも非表示（既定値） |
| `/UseOutlines` | アウトライン（しおり）パネルを表示 |
| `/UseThumbs` | ページサムネイルパネルを表示 |
| `/FullScreen` | 全画面モード |
| `/UseOC` | オプショナルコンテンツパネルを表示 |
| `/UseAttachments` | 添付ファイルパネルを表示 |

## 3. ページツリー（Page Tree）

### 3.1 ツリー構造の概要

ページオブジェクトは単なる一次元配列ではなく、**平衡木（Balanced Tree）に似た階層構造**で編成されます。これにより数千ページに及ぶ文書でも効率的にページを検索できます。

```text
                    /Pages (Root)
                   /Count 100
                  /      \
           /Pages         /Pages
          /Count 50      /Count 50
         /   \           /    \
      /Pages  /Pages  /Pages  /Pages
      ...     ...     ...     ...
        |       |       |       |
      /Page   /Page   /Page   /Page
      (末端)   (末端)   (末端)   (末端)
```

### 3.2 ページツリーノード（`/Pages`）

子ノードを束ねる中間ノードの辞書です。

```pdf
2 0 obj
<< /Type /Pages
   /Kids [3 0 R 4 0 R 5 0 R]
   /Count 3
>>
endobj
```

#### 必須エントリ

| キー | 型 | 説明 |
| :--- | :--- | :--- |
| `/Type` | 名前 | 必ず `/Pages` |
| `/Kids` | 配列 | 子ノード（`/Pages` または `/Page`）への間接参照の配列 |
| `/Count` | 整数 | このノード配下にある**末端ページ（`/Page`）の総数** |

#### 任意エントリ（子へ継承可能）

| キー | 型 | 説明 |
| :--- | :--- | :--- |
| `/Parent` | 間接参照 | 親ノードへの参照（ルートノードには存在しない） |
| `/MediaBox` | 配列 | ページの物理的な寸法 |
| `/Resources` | 辞書 | 描画リソース辞書 |
| `/CropBox` | 配列 | トリミング領域 |
| `/Rotate` | 整数 | ページの回転角度（`0`, `90`, `180`, `270`） |

### 3.3 ページオブジェクト（`/Page`）

末端の葉ノードです。1 枚のページを描画するために必要な情報を持ちます。

```pdf
3 0 obj
<< /Type /Page
   /Parent 2 0 R
   /MediaBox [0 0 612 792]
   /Resources << /Font << /F1 6 0 R >> >>
   /Contents 4 0 R
>>
endobj
```

#### 必須エントリ

| キー | 型 | 説明 |
| :--- | :--- | :--- |
| `/Type` | 名前 | 必ず `/Page` |
| `/Parent` | 間接参照 | 親の `/Pages` ノードへの逆参照 |

#### 実質必須（直接定義または親からの継承が必要）

| キー | 型 | 説明 |
| :--- | :--- | :--- |
| `/MediaBox` | 配列 | ページの物理的寸法 `[llx lly urx ury]`（1 pt = 1/72 インチ） |
| `/Resources` | 辞書 | 描画に使用されるリソース定義（[04章](./04_resources_graphics_state.md)） |

#### 主要な任意エントリ

| キー | 型 | 説明 |
| :--- | :--- | :--- |
| `/Contents` | 間接参照 or 配列 | 描画命令のコンテンツストリーム。配列の場合は記載順に連結して処理 |
| `/CropBox` | 配列 | 表示・印刷時のクリッピング領域（既定値は `/MediaBox`） |
| `/BleedBox` | 配列 | 裁ち落とし領域（既定値は `/CropBox`） |
| `/TrimBox` | 配列 | 仕上がりサイズ（既定値は `/CropBox`） |
| `/ArtBox` | 配列 | コンテンツ領域（既定値は `/CropBox`） |
| `/Rotate` | 整数 | 表示時の時計回り回転角度（`0`, `90`, `180`, `270` 度。既定値は `0`） |
| `/Annots` | 配列 | ページ上の注釈（アノテーション）のリスト |
| `/Thumb` | ストリーム | ページのサムネイル画像 |
| `/UserUnit` | 実数 | ユーザー空間の単位倍率（PDF 1.6 以降、既定値 `1.0`） |

### 3.4 ページサイズの定義（ボックスモデル）

PDF は用途別に 5 種類の矩形ボックスを定義します。

```text
+------------------------------------------+
| MediaBox (物理的なメディアサイズ)           |
|  +--------------------------------------+|
|  | BleedBox (裁ち落とし領域)              ||
|  |  +----------------------------------+||
|  |  | TrimBox (仕上がりサイズ)           |||
|  |  |  +------------------------------+|||
|  |  |  | ArtBox (コンテンツ領域)        ||||
|  |  |  +------------------------------+|||
|  |  +----------------------------------+||
|  +--------------------------------------+|
+------------------------------------------+
※ 上図は典型的な入れ子関係の例であり、常にこの包含順になるとは限らない。
```

#### 座標フォーマット・正規化・交差規則

```text
[llx lly urx ury]
  llx: 左下 X 座標 (Lower-Left X)    urx: 右上 X 座標 (Upper-Right X)
  lly: 左下 Y 座標 (Lower-Left Y)    ury: 右上 Y 座標 (Upper-Right Y)
  単位: PostScript ポイント (1 pt = 1/72 インチ)
```

- **対角の正規化（ISO 32000-1 §7.9.5）**: 対角 2 点はどちらの順序でも書けるため、各軸の最小値・最大値で正規化する。`[612 792 0 0]` も `[0 792 612 0]` も `[0 0 612 792]` と等価であり、幅は `max_x - min_x`、高さは `max_y - min_y` となる。
- **既定値（ISO 32000-1 §7.7.3.3 表 30）**: `CropBox` の既定値は `MediaBox`、`BleedBox`・`TrimBox`・`ArtBox` の既定値はそれぞれ `CropBox`。
- **MediaBox との交差（ISO 32000-1 §14.11.2）**: `CropBox`・`BleedBox`・`TrimBox`・`ArtBox` が `MediaBox` の外へはみ出す場合は、`MediaBox` との交差領域を有効領域とする。

#### 標準的なページサイズ

| サイズ名 | MediaBox 値 | 寸法 |
| :--- | :--- | :--- |
| Letter | `[0 0 612 792]` | 8.5 × 11 インチ |
| A4 | `[0 0 595.276 841.89]` | 210 × 297 mm |
| A3 | `[0 0 841.89 1190.55]` | 297 × 420 mm |
| Legal | `[0 0 612 1008]` | 8.5 × 14 インチ |
| B5 | `[0 0 498.898 708.661]` | 176 × 250 mm |

#### pdfmod（Rust）の実装方針

- `Rectangle` / `PageBoxes` は**継承および間接参照の解決が終わった数値配列**を入力として扱う（継承・参照解決は §4.1 の上位処理が担当）。未解決の参照要素が渡された場合は検証エラーとするが、PDF 構文として参照自体が不正という意味ではない。
- 矩形の交差演算では、**離れた矩形同士は `None`**、**辺や点で接する交差は幅または高さが `0` の矩形**として区別する。

## 4. ページ属性の継承メカニズム

### 4.1 継承ルール

ISO 32000 により、次の 4 つの属性だけがページツリー階層を通じて親 `/Pages` から子へ**継承可能**です。

| 継承可能な属性 | 説明 | 既定値（祖先にも無い場合） |
| :--- | :--- | :--- |
| `/MediaBox` | ページの物理的寸法 | なし（必須。未定義ならエラー） |
| `/CropBox` | トリミング領域 | 解決済み `/MediaBox` と同じ |
| `/Resources` | 描画リソース辞書 | 空辞書（最も近い有効な辞書全体を採用し、祖先とはマージしない） |
| `/Rotate` | 回転角度 | `0` 度 |

#### 継承属性に含まれる間接参照

ISO 32000-1 §7.3.10 により、属性値自体や配列要素も間接参照で書かれます。

| 記述例 | 解決対象 |
| :--- | :--- |
| `/MediaBox 10 0 R` | 属性値自体 |
| `/MediaBox [0 0 10 0 R 792]` | 配列の各要素 |
| `/Kids 20 0 R` | 値自体（要素は子ノードへの参照なので、ここでは解決しない） |

#### pdfmod の実装方針（無効値フォールバックと Rust `page_attributes`）

- **フォールバック方針**: 局所値が読み取れない場合（参照未解決・型不正など）は致命的エラーにせず警告を報告し、未設定扱いとして祖先の継承値へフォールバックする。`/MediaBox` は祖先にも有効値が無い場合にのみエラー（TS は `MEDIABOX_NOT_FOUND`、Rust は `MissingMediaBox`）とする。
- **欠落・直接 `null` と参照 `null` の区別**: キー欠落や直接 `null` は通常の未設定（警告なし）として扱う。一方、間接参照の解決結果が `null` になった場合は不正な値の型として警告したうえで探索を続ける。
- **参照の解決段数**: TypeScript の継承解決層は 1 段解決とし、多段参照・循環参照はオブジェクト解決層に委ねる。Rust の `ObjectResolver::page_attributes(&Page)` は `page_tree` で記録したカタログの根を終点として `/Parent` チェーンを反復走査する。

**Rust `ObjectResolver::page_attributes` の走査手順**:

1. ページ自身から開始し、まだ確定していない属性だけを参照解決・検証する。
2. 有効なら確定、無効なら「ノード・キー・原因」を警告して祖先の探索を続ける。
3. `/Parent` が間接参照であることを確認して親へ進む。根以外での欠落・`null`、参照解決失敗、辞書でない親、再訪による循環、および根ノードに `/Parent` がある場合はエラーとする。
4. 全属性が確定した後も根まで親チェーンの整合性を検証し、最後に未確定属性へ既定値を適用する（`/Rotate` は 90 の倍数の整数を剰余で `0 / 90 / 180 / 270` に正規化）。

| 検証範囲外（`PageAttributes` の責務外） | 委譲先 |
| :--- | :--- |
| `CropBox` 等と `MediaBox` との交差適用 | `PageBoxes`（§3.4） |
| `/Resources` 内部の間接参照解決・必要リソース有無の検証 | コンテンツストリーム・リソース処理層（[04章](./04_resources_graphics_state.md)） |
| `/Kids` と `/Parent` の相互一致・親の `/Type` 整合性 | 対象外（親チェーン自体の深さ上限は設けず、多段参照上限のみ `ObjectResolver` に従う） |

### 4.2 継承メカニズムの落とし穴

**ライブラリ開発者が最も陥りやすいアーキテクチャ上の罠**は、継承されている `/Resources` の**シャドウイング（隠蔽）**です。

```text
ページツリー:
  /Pages (Root)
    /Resources << /Font << /F1 5 0 R /F2 6 0 R >> >>   ← 親に定義
    /Kids [3 0 R]
      /Page (obj 3)
        /Parent 2 0 R   ※ /Resources は未定義 → 親から継承

[危険な更新手順]
  1. ページ辞書に /Resources が無いので空辞書 << >> を直接セットする
  2. そこへ新しいフォント /F3 だけを追加する
  → 親の /F1, /F2 がシャドウイングされ、既存のテキスト描画がすべて壊れる！
```

#### 正しい更新手順（コピーオンライト）

1. 対象ページ自身に直接 `/Resources` が定義されているか確認する。
2. 未定義の場合、親チェーンから継承中の `/Resources` を取得する。
3. 継承元の辞書があればディープコピーしてページ自身へ設定する（無ければ空辞書を設定）。
4. ローカル化された `/Resources` に対して新しいエントリを追加する。

### 4.3 ページツリーの走査アルゴリズム

#### 概念的な 2 つのアクセス方式（ISO 32000 の前提）

- **`/Count` を使ったランダムアクセス**: 各 `/Pages` ノードの `/Count`（配下の葉数）を使って目的のページ番号が含まれる部分木だけへ降りることで、平衡木なら $O(\log n)$ でページへ到達できる（ただし `/Count` が正確であることが前提）。
- **全ページの順次走査**: ルート `/Pages` から `/Kids` を左から順に深さ優先で辿り、`/Page` へ到達するたびに訪問する。循環参照による無限ループを防ぐため、訪問済みオブジェクト ID を追跡する。

#### pdfmod（Rust）の走査・回復方針

`ObjectResolver::page_tree(&Catalog)` は `/Count` の誤りを信用せず、明示スタックによる非再帰の深さ優先走査で実ページ列を構築します。

- **非再帰・独自深さ上限なし**: 明示スタックにノードの進入・退出を積むためコールスタックを消費せず、循環・共有は再訪時点で打ち切るため有限入力で必ず終了する（正当な深い木を拒否しない方針。ただしメモリ・処理時間の上限保証ではない）。
- **間接参照の扱い**: `/Type`・`/Kids`・`/Count` の値自体が間接参照なら解決してから検証する（解決結果の `null` は欠落扱い）。`/Count` の型不正は警告だが、参照解決失敗自体はエラーとする。
- **検証範囲外**: `/Parent` の参照整合性やページ属性の継承解決は列挙 API では行わない。

以下の表はライブラリの回復・検証方針であり、必須キーの省略を PDF 仕様が許容するという意味ではありません。

| 条件 | Rust 実装の取り扱い |
| :--- | :--- |
| `/Type /Pages` | `/Kids` を辿る。カタログの根も Pages であることを検証 |
| `/Type /Page` | 葉として追加。根が Page なら `RootIsPage` エラー |
| `/Type` が欠落・`null` | 解決済み `/Kids` が非 `null` なら Pages、`/Kids` 不在かつ `/Parent` が間接参照なら Page と推定し `InferredType` 警告。根にも同じ規則を適用し、推定根拠が無ければ `CannotInferType` エラー |
| `/Type` が未知の名前・不正型 | 推定せずエラー |
| `/Count` と実葉数が不一致 | 各 Pages ノードで `CountMismatch` 警告。実走査結果を正とし、`/Count` で枝刈り・水増し・事前領域確保しない |
| `/Count` が欠落・`null`・非整数・負数 | `MissingCount` または `InvalidCount` 警告を出し走査を続行 |
| `/Kids []` | 空のページ列として受理（実走査数 `0`） |
| Pages の `/Kids` が欠落・`null`・非配列、または要素が非参照 | 構造エラー（要素が非参照なら `InvalidKid` に親 ID・0 起点位置・実型を保持） |
| ノードが非辞書・参照解決失敗 | エラー（`NotADictionary` や `Resolution`。子を黙って省いた部分列は返さない） |

#### 循環（`Cycle`）と共有ノード（`RepeatedNode`）の区別

```text
[Cycle: 祖先への逆戻り]           [RepeatedNode: 異なる経路からの共有 (DAG)]
   Pages A (走査中)                   Pages Root
      │                                /      \
      ▼                           Pages B    Pages C
   Pages B (走査中)                    \      /
      │                                 ▼    ▼
      └──→ Pages A を再訪！             Page X (2回目に到達)
```

- 走査中の `/Pages` ノードを**祖先集合**（オブジェクト番号 + 世代番号）へ登録し、退出時に除去する（`/Count` が不正でも必ず除去する）。
- 再訪時に祖先集合へ含まれていれば **`Cycle { node }`**、退出済みの訪問済み ID なら **`RepeatedNode { node }`** として区別し、いずれもエラーとする（DAG の共有はページ番号と単一 `/Parent` 継承の整合を壊すため、先勝ち回復も行わず拒否する）。
- なお、辞書自身の間接参照チェーンが循環している場合は `Resolution { cause: ResolveError::Cycle(..), .. }` となり、ページツリーの `Cycle` とは別エラーになる。

#### 結果とページ位置型

| 型 / メソッド | 仕様 |
| :--- | :--- |
| `PageTree` | 文書順のページ列と警告一覧を保持 |
| `PageIndex` | 0 起点インデックス。`number()` は 1 起点表現がオーバーフローするとき `None` |
| `PageNumber` | 1 起点ページ番号（`0` を構築不可）。`Into<PageIndex>` で変換可能 |
| `PageTree::page(PageIndex)` | 実走査数を基準に範囲検証し、範囲外なら `None` |

### 4.4 Rust の文書・ページ公開 API

`PdfDocument::open(&[u8])` は入力バイト列を借用し、ヘッダ・xref・トレイラ・カタログを検証して文書ハンドルを構築します。`PdfDocument` / `PdfPage` / `DocumentError` とページ位置型はクレート直下から公開されます。

#### 遅延解決の原則

構築時には**ページ列・継承属性・`/Info`・`/Contents` を先読みしません**。各メソッド呼び出し時に必要な分だけ解決します。

| API | 振る舞い |
| :--- | :--- |
| `page(PageIndex)` | 明示スタック走査を対象の葉まで実行し、そのページだけの継承属性を解決して `Ok(Some(PdfPage))` を返す（範囲外は `Ok(None)`）。`PageNumber` も `Into<PageIndex>` で渡せる。`/Count` による枝刈りは行わない |
| `page_count()` | 初回呼び出し時に構造全体を走査して実葉数を記憶する（属性・Resources・Contents の参照先は解決しない）。構造全体の不正はこの全走査で検出される |
| `page_tree_warnings()` | 直近の成功した走査の警告を返す（全走査成功後はその警告を保持。部分走査では後続ノードや未退出祖先の `/Count` 不一致は未検証） |
| `PdfPage` | 継承解決済みの `MediaBox`・`CropBox`・`Rotate`・`Resources` と元のページ辞書を保持。`resources()` 内部の参照は未解決のまま保持し、`resolve(IndirectRef)` で必要時に取得する |
| `PdfPage::contents()` / `content_streams(&PdfPage)` | `contents()` はページ固有の未解決値を返す。`content_streams()` は単一ストリーム・直接配列・配列参照を記述順の Stream 列へ解決する（不在・`null` は空列、非ストリーム要素はページ・位置・実型付きエラー）。フィルタ展開・結合・命令解析はこの API の責務外 |
| `document_info()` | `/Info` を要求時に取得する（辞書全体・項目ごとの失敗扱いは §5 および [ドキュメント情報辞書ガイド](../guides/document-info.html) 参照） |

> **共通前提**: 取得した `PdfPage` や `IndirectRef` は取得元の `PdfDocument` でのみ使用する。暗号化文書は resolver と同じく拒否する。入力は借用し、解決済みオブジェクトの所有は `Rc` で共有する。

## 5. ドキュメント情報辞書

トレイラの `/Info` エントリから参照されるメタデータ辞書です。

```pdf
5 0 obj
<< /Title (Sample PDF)
   /Author (John Doe)
   /Subject (PDF Specification)
   /Creator (MyApp)
   /Producer (MyPDFLib 1.0)
   /CreationDate (D:20260314120000+09'00')
   /ModDate (D:20260314120000+09'00')
>>
endobj
```

### 5.1 情報辞書のエントリ

| キー | 型 | 説明 |
| :--- | :--- | :--- |
| `/Title` | テキスト文字列 | ドキュメントのタイトル |
| `/Author` | テキスト文字列 | 作成者名 |
| `/Subject` | テキスト文字列 | ドキュメントの主題 |
| `/Keywords` | テキスト文字列 | キーワード |
| `/Creator` | テキスト文字列 | 元の文書を作成したアプリケーション名 |
| `/Producer` | テキスト文字列 | PDF へ変換したアプリケーション名 |
| `/CreationDate` | 日時文字列 | 作成日時（§5.2） |
| `/ModDate` | 日時文字列 | 最終更新日時（§5.2） |
| `/Trapped` | 名前 | トラッピング状態（`/True`, `/False`, `/Unknown`） |

### 5.2 PDF日時文字列フォーマット

```text
D:YYYYMMDDHHmmSSOHH'mm'

  D:      プレフィックス（推奨・実質標準）
  YYYY    年（4 桁、必須）
  MM      月（01–12、省略時は 01）
  DD      日（01–31、省略時は 01）
  HH      時（00–23、省略時は 00）
  mm      分（00–59、省略時は 00）
  SS      秒（00–59、省略時は 00）
  O       UTC との関係: '+' / '-' / 'Z'
  HH'mm'  UTC からの時差（ISO 32000-2 では末尾アポストロフィ省略可）

例: D:20260314120000+09'00'  →  2026年3月14日 12:00:00 JST
```

年（`YYYY`）以降のフィールドは末尾側から階層的に省略できます（例: `D:2026`、`D:20260314`）。

## 6. アウトライン（しおり/ブックマーク）

ドキュメントカタログの `/Outlines` から参照される階層的なナビゲーション構造です。各項目は双方向リンクリスト（`/Prev`・`/Next`）と親子リンク（`/Parent`・`/First`・`/Last`）で連結されます。

```pdf
10 0 obj
<< /Type /Outlines
   /First 11 0 R
   /Last 12 0 R
   /Count 3
>>
endobj

11 0 obj
<< /Title (Chapter 1)
   /Parent 10 0 R
   /Next 12 0 R
   /Dest [3 0 R /FitH 720]
>>
endobj
```

### 6.1 アウトラインエントリのキー

| キー | 型 | 説明 |
| :--- | :--- | :--- |
| `/Title` | テキスト文字列 | 表示テキスト |
| `/Parent` | 間接参照 | 親エントリへの参照 |
| `/First` | 間接参照 | 最初の子エントリ |
| `/Last` | 間接参照 | 最後の子エントリ |
| `/Prev` | 間接参照 | 前の兄弟エントリ |
| `/Next` | 間接参照 | 次の兄弟エントリ |
| `/Count` | 整数 | 子孫エントリの数（負値の場合は折りたたみ状態を表す） |
| `/Dest` | 配列 or 名前 | ジャンプ先のページ位置 |
| `/A` | 辞書 | クリック時に実行するアクション |
