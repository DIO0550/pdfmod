## 1. 概要

ページ辞書（または Form XObject）の `/Resources` 辞書は、コンテンツストリーム内で使われる**ローカルな識別名**（例: `/F1`, `/Im0`, `/GS1`）と、ファイル内の**グローバルなインダイレクトオブジェクト**とを結びつける**スコープ付きのルックアップテーブル**です。

## 2. リソース辞書の構造

```pdf
<< /Resources
   << /Font << /F1 6 0 R /F2 7 0 R >>
      /XObject << /Im0 8 0 R /Fm1 9 0 R >>
      /ExtGState << /GS1 10 0 R >>
      /ColorSpace << /CS1 11 0 R >>
      /Pattern << /P1 12 0 R >>
      /Shading << /SH1 13 0 R >>
      /ProcSet [/PDF /Text /ImageB /ImageC /ImageI]
   >>
>>
```

## 3. リソースカテゴリ詳細

### 3.1 `/Font`（フォント辞書）

コンテンツストリーム内のフォント識別名をフォント辞書オブジェクトへマッピングします。

```pdf
% リソース定義
/Font << /F1 6 0 R     % Tf オペレータで "/F1" として参照
         /F2 7 0 R     % Tf オペレータで "/F2" として参照
         /TT0 15 0 R   % 命名規則は任意
      >>

% コンテンツストリームでの使用例
BT
/F1 12 Tf              % /F1 フォントを 12pt で設定
(Hello) Tj
ET
```

#### 名前解決の基本フロー

1. ストリーム内でフォント名（例: `/F1`）を検出する。
2. 現在のスコープの `/Resources` → `/Font` サブ辞書を参照する。
3. `/F1` に対応するオブジェクト（直接辞書または間接参照 `6 0 R`）を解決してフォント辞書を得る。
4. 後段でフォント種別・エンコーディング・フォントプログラムを読み込む（[06章](./06_font_architecture.md)）。

#### pdfmod の実装方針（名前解決と状態保持）

| 項目 | 方針 |
| :--- | :--- |
| 解決対象と戻り値 | `/Font` サブ辞書と各フォント辞書は直接値・間接参照のどちらでも解決する。成功値は**辞書に限定**し、辞書内部のフォント種別・エンコーディング検証は後段へ委ねる |
| 未解決の扱い | 名前または `/Font` が存在しない場合、あるいは解決結果が辞書でない場合は、エラーではなく「未解決」として回復する |
| 参照解決エラーの扱い | 参照解決処理自体が返したエラーは、未解決へ潰さず元の原因を保ったまま伝播する |
| `Tf` とテキスト状態 | `Tf` が指定したフォント名とサイズはテキスト状態へ保持する。フォントが未解決であっても、文字間隔・単語間隔・水平倍率・行送り・描画モード・ライズは変更しない |
| スコープ分離 | 現在のページ・フォームのリソーススコープのみを参照し、別スコープの同名フォントへフォールバックしない |

### 3.2 `/XObject`（外部オブジェクト辞書）

再利用可能な画像やベクター図形ストリームをマッピングします。

```pdf
/XObject << /Im0 8 0 R     % ラスタ画像
            /Fm1 9 0 R     % フォーム XObject
         >>
```

#### サブタイプ一覧

| サブタイプ | 説明 |
| :--- | :--- |
| `/Image` | ラスタ画像（JPEG・PNG 等） |
| `/Form` | カプセル化された再利用可能なベクター描画命令ストリーム |
| `/PS` | PostScript フラグメント（レガシー、非推奨） |

#### Image XObject の主要エントリ

| キー | 型 | 説明 |
| :--- | :--- | :--- |
| `/Type` | 名前 | `/XObject` |
| `/Subtype` | 名前 | `/Image` |
| `/Width` | 整数 | 画像の幅（ピクセル） |
| `/Height` | 整数 | 画像の高さ（ピクセル） |
| `/ColorSpace` | 名前 or 配列 | 色空間（`/DeviceRGB`、`/DeviceGray` など） |
| `/BitsPerComponent` | 整数 | 1 成分あたりのビット数（1, 2, 4, 8, 16） |
| `/Filter` | 名前 or 配列 | 圧縮フィルタ（`/DCTDecode` = JPEG など） |
| `/SMask` | ストリーム | ソフトマスク（アルファチャンネル） |
| `/Mask` | ストリーム or 配列 | ハードマスクまたはカラーキーマスク |
| `/ImageMask` | 真偽値 | 現在の描画色で塗るステンシル画像の指定（既定値 `false`） |

#### Form XObject の主要エントリ

| キー | 型 | 説明 |
| :--- | :--- | :--- |
| `/Type` | 名前 | `/XObject` |
| `/Subtype` | 名前 | `/Form` |
| `/BBox` | 配列 | バウンディングボックス `[llx lly urx ury]` |
| `/Matrix` | 配列 | フォーム空間からユーザー空間への変換行列（既定値: 単位行列） |
| `/Resources` | 辞書 | フォーム内だけで有効なリソース辞書（独自スコープ） |

#### コンテンツストリームでの使用例

```pdf
q                     % グラフィックスステート保存
100 0 0 100 50 700 cm % 変換行列設定（サイズ 100x100、位置 (50, 700)）
/Im0 Do               % XObject "/Im0" を描画
Q                     % グラフィックスステート復元
```

#### pdfmod の実装方針（取得・回復と Form 入れ子実行）

**1. 取得と属性回復（`PdfResources.getXObject`）**:

- 現在のスコープで名前を引き、ストリームは**未復号バイトのまま**保持する。名前やストリームが無い場合は未解決、参照先の解析エラーはそのまま返す。
- ストリームが存在すれば、`/Subtype` が欠落・不正・未知でも取得する（未知の名前は元の綴りを保持、非推奨の `/PS` は独立種別）。
- 不正な画像属性や `/BBox` はその属性だけを未設定にする。矩形は対角 2 点を正規化し、不正な `/Matrix` は省略時と同じ単位行列へ回復する。

**2. Form XObject の入れ子実行（ISO 32000-1:2008 §8.10.2）**:

```text
/Fm1 Do
  ├─ 1. 現在のグラフィックスステートを暗黙に保存
  ├─ 2. 新 CTM = Form の /Matrix × 現在の CTM
  ├─ 3. Form の /BBox を新 CTM で変換し、既存クリッピング領域と交差
  ├─ 4. /Resources 切替（あれば辞書全体・空辞書でも切替、省略時は呼び出し元を継承）
  ├─ 5. Form 内のコンテンツストリームを実行
  └─ 6. 呼び出し元のグラフィックスステートへ復元
```

| 状況 | pdfmod の挙動 |
| :--- | :--- |
| 対応フィルタ | 同期実行前に準備。未圧縮、および単一の `FlateDecode` / `LZWDecode` を受理 |
| `/BBox` 無効・`/Resources` 不正・復号不能 | `Do` で警告を記録してその Form だけをスキップ |
| Form 命令列内の構文・オペランドエラー | 実行エラーとして返す |
| 実行中の同一ストリームへの再入 | `FORM_XOBJECT_CYCLE` 警告を出しその呼び出しをスキップ（同じ Form の順次呼び出しは許可） |
| 入れ子 33 段目以降の呼び出し | `FORM_XOBJECT_TOO_DEEP` 警告を出しその呼び出しをスキップ |
| 入れ子内の警告位置 | 外側の `Do` の位置と Form 内のバイト位置の両方を残す |
| Image XObject に対する `Do` | 未復号の画像・参照元リソース・描画時の状態を `images` へ描画順で記録 |

### 3.3 `/ExtGState`（拡張グラフィックスステート辞書）

単一オペレータでは表せない透明度・ブレンドモード・ソフトマスクなどの描画状態を辞書で定義し、`gs` オペレータで一括適用します。

```pdf
/ExtGState << /GS1 10 0 R >>

% コンテンツストリームでの使用例
/GS1 gs
```

#### 主要エントリ

| キー | 型 | 説明 | 既定値 |
| :--- | :--- | :--- | :--- |
| `/Type` | 名前 | `/ExtGState`（描画パラメータではない） | — |
| `/LW` | 実数 | 線の太さ | `1.0` |
| `/LC` | 整数 | 線端の形状（`0`=Butt, `1`=Round, `2`=Square） | `0` |
| `/LJ` | 整数 | 線接合の形状（`0`=Miter, `1`=Round, `2`=Bevel） | `0` |
| `/ML` | 実数 | マイター限界値 | `10.0` |
| `/D` | 配列 | 破線パターン `[[dash_array] phase]` | `[[] 0]` |
| `/RI` | 名前 | レンダリングインテント | `/RelativeColorimetric` |
| `/OP` | 真偽値 | ストロークのオーバープリント | `false` |
| `/op` | 真偽値 | フィルのオーバープリント | `false` |
| `/OPM` | 整数 | オーバープリントモード | `0` |
| `/Font` | 配列 | `[font_ref size]` フォント辞書とサイズ | — |
| `/ca` | 実数 | フィルの不透明度（`0.0`〜`1.0`） | `1.0` |
| `/CA` | 実数 | ストロークの不透明度（`0.0`〜`1.0`） | `1.0` |
| `/BM` | 名前 or 配列 | ブレンドモード | `/Normal` |
| `/SMask` | 辞書 or 名前 | ソフトマスク辞書または `/None` | `/None` |
| `/AIS` | 真偽値 | アルファソースフラグ | `false` |
| `/TK` | 真偽値 | テキストノックアウトフラグ | `true` |

#### ブレンドモード一覧

| 種別 | 名前 | 説明 |
| :--- | :--- | :--- |
| 分離可能モード | `/Normal` | 通常（既定値。`/Compatible` も同等扱い） |
| 分離可能モード | `/Multiply` / `/Screen` / `/Overlay` | 乗算 / スクリーン / オーバーレイ |
| 分離可能モード | `/Darken` / `/Lighten` | 比較（暗） / 比較（明） |
| 分離可能モード | `/ColorDodge` / `/ColorBurn` | 覆い焼きカラー / 焼き込みカラー |
| 分離可能モード | `/HardLight` / `/SoftLight` | ハードライト / ソフトライト |
| 分離可能モード | `/Difference` / `/Exclusion` | 差の絶対値 / 除外 |
| 非分離モード | `/Hue` / `/Saturation` / `/Color` / `/Luminosity` | 色相 / 彩度 / カラー / 輝度 |

#### pdfmod の実装方針（適用と回復）

- **準備とスコープ**: 同期インタプリタ実行前に `ExtGStateResources.fromResources` で現在スコープを解決し、`OperatorRegistry.createDefault` または `registerGraphicsStateOperators` へ渡す（スコープを跨いで共有しない）。カテゴリの参照解決エラーは準備時に返し、各名前の参照エラーはその名前の `gs` 実行時に伝播する。
- **適用対象キー**: `/LW`, `/LC`, `/LJ`, `/ML`, `/D`, `/CA`, `/ca`, `/BM`, `/SMask`, `/Font` を適用する（`/Type` は読み飛ばす）。省略キーは現在値を保持し、専用命令と同じ `GraphicsState.update` / `TextState.withFont` で更新する。
- **固有パラメータの扱い**:
  - `/Font`: `[フォント辞書の参照（直接辞書も可）, サイズ]` を読む。`Tf` の名前指定と `gs` の辞書指定は同一のフォント選択の別バリアントとして保持し、後の指定が前を置き換える（`fontName` はこの選択から導出）。
  - `/BM`: 名前配列なら先頭から最初の対応モードを採用し、対応モードが無ければ `Normal`。`Compatible` は `Normal` 扱い。非分離 4 モードも状態として保持する。
  - `/SMask`: `/None` または辞書をそのまま保持（辞書内部検証・透明グループ描画・ピクセル合成は後段の責務）。
  - 線幅・マイター・破線: 有限の数値のみ受理（値域検証は専用オペレータと同様に対象外）。
- **初期値と `q` / `Q`**: 不透明度の初期値は輪郭・塗りとも `1`、ブレンドモードは `Normal`、ソフトマスクは `/None`。これらとフォント選択も `q` / `Q` 保存・復元の対象となる。

| 状況 | 警告コード / 挙動（位置は `gs` 命令のバイト位置） |
| :--- | :--- |
| 名前または辞書が存在しない | `EXT_GSTATE_NOT_FOUND` を報告し、現在状態を保持 |
| 未知・未対応のキー | `EXT_GSTATE_UNSUPPORTED_ENTRY` を報告し、そのキーだけ無視 |
| 不正な型・不透明度の範囲外など | `EXT_GSTATE_INVALID_ENTRY` を報告し、そのキーだけ無視 |
| 参照解決エラー | 警告へ置き換えずエラーとして伝播 |

### 3.4 `/ColorSpace`（色空間辞書）

デバイス非依存の色空間や特殊色空間を名前で定義します。

```pdf
/ColorSpace << /CS1 [/ICCBased 11 0 R]
               /CS2 [/Indexed /DeviceRGB 255 12 0 R]
            >>
```

#### 色空間の分類と成分数

| カテゴリ | 色空間名 | 数値成分数 | 説明 |
| :--- | :--- | :--- | :--- |
| デバイス依存 | `/DeviceGray` | 1 | グレースケール |
| デバイス依存 | `/DeviceRGB` | 3 | RGB |
| デバイス依存 | `/DeviceCMYK` | 4 | CMYK |
| CIE ベース | `/CalGray` | 1 | キャリブレーテッドグレースケール |
| CIE ベース | `/CalRGB` | 3 | キャリブレーテッド RGB |
| CIE ベース | `/Lab` | 3 | CIE L\*a\*b\* |
| CIE ベース | `/ICCBased` | `/N`（1・3・4） | ICC プロファイルストリームの `/N` による |
| 特殊 | `/Indexed` | 1 | パレット添字（基底が RGB でもオペランドは添字 1 個。基底定義は別途保持） |
| 特殊 | `/Pattern` | 0 または基底の成分数 | 着色パターンは 0、非着色パターンは基底色空間の成分数 + パターン名 |
| 特殊 | `/Separation` | 1 | 特色（スポットカラー） |
| 特殊 | `/DeviceN` | 色材名配列の長さ | 複数特色の組み合わせ |

#### コンテンツストリームでの選択と初期色

- `cs`（塗り）/ `CS`（輪郭）で色空間を切り替えると、色はその色空間の初期値へリセットされる（デバイス色は黒、`Separation` / `DeviceN` は全成分 `1`、その他の数値成分は `0`。Lab の成分範囲クリップは解決層では行わない）。
- `sc` / `SC` / `scn` / `SCN` が現在の色空間に必要な数の数値成分を受け取る。`Pattern` には `scn` / `SCN` を使い、数値成分の後ろにパターン名を指定する。

#### pdfmod の実装方針（準備・回復・責務境界）

- **準備と参照解決**: 同期インタプリタ実行前に `ColorSpaceResources.fromResources(resources, resolveRef)` で現在スコープを解決し、`OperatorRegistry.createDefault` または `registerColorOperators` へ渡す（別ページ・フォームと共有しない）。`/ColorSpace` カテゴリ・各定義・配列族名・ICCBased プロファイルと `/N`・DeviceN 名前配列と各名前・Indexed / Pattern 基底・CIE パラメータ辞書の各間接参照を解決する（`/Resources` 自体の継承解決はページ属性解決を使用）。
- **エラー伝播のタイミング**: カテゴリ自体の参照解決エラーは準備時に返し、個別定義の参照エラーは名前ごとに保持して `cs` / `CS` で実際に選択されたときに伝播する。
- **不明色空間と再帰上限**: 定義の再帰は **32 段**を上限とし、上限超過時も不明な定義として回復する。不明な色空間は以前の色空間の成分数を引き継がず「成分数不明」として保持する（以後の色命令は数値型だけ検証し個数一致は検証しない。ただし `Indexed` は基底が不明でも添字は常に 1 成分）。
- **責務境界**: この層は「色空間の族・成分数・色値の保持（および `q` / `Q` での保存復元）」までを担う。ICC プロファイル変換・CIE パラメータの数値検証・パレット展開・特色の関数評価・パターン描画は後段の責務。

| 状況 | コード（警告 / エラー） |
| :--- | :--- |
| 不在の名前（`cs` / `CS` 直接指定・定義内別名・基底参照） | 警告: `COLOR_SPACE_NOT_FOUND`（選択命令の位置で報告） |
| 配列先頭に未知の族名 | 警告: `COLOR_SPACE_UNSUPPORTED` |
| 成分数確定に必要な値の不正・欠落・循環 | 警告: `COLOR_SPACE_INVALID` |
| 既知の成分数の過不足 | エラー: `OPERATOR_OPERAND_COUNT_MISMATCH` |
| オペランド型の不一致 | エラー: `OPERATOR_OPERAND_TYPE_MISMATCH` |
| Pattern 色空間に対して `sc` / `SC` を使用 | エラー: `OPERATOR_ILLEGAL_STATE` |

### 3.5 `/Pattern`（パターン辞書）

タイリングパターンやシェーディングパターンを定義します。

| パターン種別 | `/PatternType` 値 | 説明 |
| :--- | :--- | :--- |
| タイリングパターン | `1` | 繰り返し描画される小さな図形セル |
| シェーディングパターン | `2` | グラデーションなどの滑らかな色変化 |

#### 属性と `scn` / `SCN` での使用ルール

- **種別 1（タイリング）**: ストリームを持ち、`/PaintType`（`1`=着色, `2`=非着色）、`/TilingType`（`1`〜`3`）、`/BBox`（4 数値）、`/XStep`・`/YStep`（有限・0 以外）、`/Resources`（辞書）、任意の `/Matrix`（6 数値、省略時は単位行列）を読み取る。pdfmod は未復号のセルストリームを保持し、内部命令は実行しない。
- **種別 2（シェーディング）**: `/Shading` を解決して §3.6 の型へ変換し、`/Matrix` と任意の `/ExtGState` 辞書を保持する（拡張状態の適用は行わない）。
- **色空間との整合**: `scn` / `SCN` の名前オペランドは現在色空間が `Pattern` のときだけ許可し、現在の `/Pattern` サブ辞書を引く（Pattern 以外で名前が渡されると型・個数エラー）。
  - 着色タイリング / シェーディングパターン → **基底色空間なし**の `Pattern` と組み合わせる。
  - 非着色タイリングパターン → **基底色空間あり**の `Pattern` と組み合わせ、数値成分数は基底色空間に従う（パターン名は数えない）。
  - 組み合わせが食い違う場合は `OPERATOR_ILLEGAL_STATE` エラー。
- 指定名と数値成分は色状態へ保存し、型付き定義は `PaintResources.patterns` から参照できる（実描画は後段）。

### 3.6 `/Shading`（シェーディング辞書）

グラデーション描画を定義し、`sh` オペレータで適用します。

| シェーディング種別 | `/ShadingType` 値 | 説明 |
| :--- | :--- | :--- |
| 関数ベース | `1` | 2D 関数による色定義 |
| 軸方向 | `2` | 2 点間の線形グラデーション |
| 放射状 | `3` | 2 円間の放射グラデーション |
| フリーフォームメッシュ | `4` | 自由形式のメッシュグラデーション |
| ラティスフォームメッシュ | `5` | 格子形式のメッシュグラデーション |
| クーンズパッチメッシュ | `6` | クーンズパッチによるメッシュ |
| テンソル積パッチメッシュ | `7` | テンソル積パッチによるメッシュ |

#### 共通属性と `sh` オペレータ

- `/ColorSpace`（名前または配列）、任意の `/Background`（数値配列）、`/BBox`（4 数値）を読み取る。色空間配列内部の解釈・背景成分数・種別固有の必須キーや値域の全面検証は後段の責務。
- 種別 4〜7 はメッシュの未復号ストリームを必須とする。未知の種別番号は元オブジェクトを保持する `Unknown` 扱いとする。
- `/Function` は元の `PdfValue` のまま保持する（間接参照の解決や関数評価は行わない）。
- `sh` は名前オペランドを正確に 1 個受け取り、現在の `/Shading` サブ辞書を引く（色・色空間・パス・クリップは変更せず、この段階では描画しない）。

#### pdfmod の実装方針（Pattern / Shading 共通の準備と回復）

- **準備とスコープ**: 同期実行前に `PaintResources.fromResources(resources, resolveRef)` で `/Pattern`・`/Shading` カテゴリ、各定義、主要属性（数値配列の各要素を含む）の間接参照を解決し、`OperatorRegistry.createDefault` または `registerColorOperators` へ渡す。別ページ・フォームへフォールバックしない。
- **参照エラーと `null` の区別**: カテゴリの参照解決エラーは準備時に、個別定義・主要属性の参照エラーは名前別に保持して `scn` / `SCN` / `sh` 実行時に返す。参照先が存在せずリゾルバが PDF の `null` を返した場合は、解決エラーではなく不正定義（警告）として扱う。
- **回復方針の境界**: 不正な `/Matrix` を単位行列へ置き換える回復は行わない。名前不在や `Unknown` パターンでも指定名と数値成分は色状態へ保存して後続命令を継続する（警告による回復は pdfmod 独自方針であり、未知定義が描画可能であることを意味しない）。

| 状況 | Pattern の警告コード | Shading の警告コード |
| :--- | :--- | :--- |
| 名前が存在しない | `PATTERN_NOT_FOUND` | `SHADING_NOT_FOUND` |
| 種別番号が未知・欠落・不正型 | `PATTERN_UNSUPPORTED` | `SHADING_UNSUPPORTED` |
| 既知種別の主要属性が不正 | `PATTERN_INVALID` | `SHADING_INVALID` |

## 4. グラフィックスステートマシン

PDF の描画命令はすべて、現在の**グラフィックスステート**（変換行列・色・線幅・クリッピング・テキスト状態・透明度など）を参照して動作します。

### 4.1 ステートの構成要素

| パラメータ | 既定値 | 主な設定オペレータ |
| :--- | :--- | :--- |
| CTM（カレント変換行列） | 単位行列 | `cm` |
| クリッピングパス | ページ全体 | `W` / `W*` |
| 色空間（ストローク / フィル） | `/DeviceGray` | `CS` / `RG` / `K`（ストローク）、`cs` / `rg` / `k`（フィル） |
| 色（ストローク / フィル） | 黒 | `SC` / `SCN` / `RG` / `K` / `G`（ストローク）、`sc` / `scn` / `rg` / `k` / `g`（フィル） |
| 線の太さ | `1.0` | `w` |
| 線端の形状 | `0` (Butt) | `J` |
| 線接合の形状 | `0` (Miter) | `j` |
| マイター限界値 | `10.0` | `M` |
| 破線パターン | 実線 (`[[] 0]`) | `d` |
| レンダリングインテント | `/RelativeColorimetric` | `ri` |
| フラットネス許容値 | `1.0` | `i` |
| 透明度・ブレンド・ソフトマスク | 不透明度 `1.0`、`/Normal`、`/None` | `gs`（`/ExtGState`） |
| テキストステート | §4.2 参照 | テキストオペレータ |

### 4.2 テキストステート

| パラメータ | 既定値 | 設定オペレータ | 説明 |
| :--- | :--- | :--- | :--- |
| 文字間隔 | `0` | `Tc` | 文字間の追加スペース |
| 単語間隔 | `0` | `Tw` | 単語間の追加スペース（スペース文字のみ適用） |
| 水平スケーリング | `100` | `Tz` | テキスト水平方向の拡大率（%） |
| テキストリーディング | `0` | `TL` | 行間隔 |
| フォント / サイズ | なし | `Tf` / `gs` | 使用フォントとサイズ |
| テキストレンダリングモード | `0` (Fill) | `Tr` | テキストの塗り・輪郭・クリップ方式 |
| テキストライズ | `0` | `Ts` | ベースラインからの垂直オフセット |

#### テキストレンダリングモード

| 値 | 説明 |
| :--- | :--- |
| `0` | フィル（塗りつぶし） |
| `1` | ストローク（輪郭） |
| `2` | フィル + ストローク |
| `3` | 不可視 |
| `4` | フィル + クリッピングパスに追加 |
| `5` | ストローク + クリッピングパスに追加 |
| `6` | フィル + ストローク + クリッピングパスに追加 |
| `7` | クリッピングパスに追加のみ |

### 4.3 ステートスタックの動作（`q` / `Q`）

グラフィックスステートは LIFO スタックで管理します。

```text
初期状態 S0
  │
  ├─ q (save)    ──→ スタックへ S0 のコピーを積む。以後 S1 として変更
  │    ├─ cm / rg / w / gs など（S1 のみを更新）
  │    └─ Q (restore) ──→ スタックから S0 をポップして現在状態を復元
  │
  ▼ S0 に戻る（CTM・クリップ・色・線・テキスト状態・透明度すべて復元）
```

- **保存・復元の対象**: §4.1 の描画パラメータ、§4.2 のテキストステート（フォント選択を含む）、および `gs` で設定した透明度・ブレンドモード・ソフトマスクのすべて。
- **保存されないもの**: 構築途中のカレントパス（パスペイント命令で消費されるため）。またテキストブロック内のテキスト行列（`Tm`）は `BT` で毎回初期化される。
