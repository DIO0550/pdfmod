# 04. リソース辞書とグラフィックスステート

## 1. 概要

ページ辞書内の `/Resources` 辞書は、コンテンツストリーム内で使用される**ローカルな識別名**と、ファイル内の任意の場所に存在する**グローバルなインダイレクトオブジェクト**とを紐づける**ローカルなルックアップテーブル**として機能する。

## 2. リソース辞書の構造

```
<< /Resources
   << /Font << /F1 6 0 R /F2 7 0 R >>
      /XObject << /Im0 8 0 R /Fm1 9 0 R >>
      /ExtGState << /GS1 10 0 R >>
      /ColorSpace << /CS1 11 0 R >>
      /Pattern << /P1 12 0 R >>
      /Shading << /SH1 13 0 R >>
      /ProcSet [/PDF /Text /ImageB /ImageC /ImageI]
   >>
>>
```

## 3. リソースカテゴリ詳細

### 3.1 /Font（フォント辞書）

コンテンツストリーム内のフォント識別名を、実際のフォント辞書オブジェクトにマッピングする。

```
/Font << /F1 6 0 R    % Tf オペレータで "/F1" として参照
         /F2 7 0 R    % Tf オペレータで "/F2" として参照
         /TT0 15 0 R  % 命名規則は任意
      >>
```

#### コンテンツストリームでの使用例
```
BT
/F1 12 Tf        % /F1 フォントを12ポイントで使用
(Hello) Tj
ET
```

#### 実装仕様
```
名前解決フロー:
  1. ストリーム内で "/F1" を検出
  2. ページの /Resources → /Font 辞書を参照
  3. /F1 キーに対応するインダイレクト参照 (6 0 R) を取得
  4. オブジェクト6を解決してフォント辞書を取得
  5. フォント辞書からフォントプログラム、エンコーディング等を読み込み
```

#### 名前解決の結果と状態の保持

- `/Font` サブ辞書と各フォント辞書は、直接値・間接参照のどちらでも解決する。
- フォント取得APIが返す成功値は辞書に限定する。辞書内部のフォント種別・エンコーディングの検証は後段が担う。
- pdfmodの回復方針として、名前または `/Font` がない場合、あるいは解決結果が辞書でない場合は、エラーではなく「未解決」を返す。
- 参照解決処理が返したエラーは、その原因を保ったまま伝播する。未解決と混同しない。
- `Tf` の指定した名前・サイズはテキスト状態に保持する。フォント取得が未解決でも、文字間隔・単語間隔・水平倍率・行送り・描画モード・ライズを変更しない。
- 名前の解決には現在のページ等のリソーススコープを使い、別のスコープの同名フォントへフォールバックしない。

### 3.2 /XObject（外部オブジェクト辞書）

再利用可能なグラフィカルコンテンツをマッピングする。

```
/XObject << /Im0 8 0 R     % ラスタ画像
            /Fm1 9 0 R     % フォームXObject
         >>
```

#### XObjectのサブタイプ

| サブタイプ | 説明 |
|:-----------|:-----|
| `/Image` | ラスタ画像（JPEG、PNG等の画像データ） |
| `/Form` | カプセル化された再利用可能なベクター図形ストリーム |
| `/PS` | PostScriptフラグメント（レガシー、非推奨） |

#### Image XObject の主要エントリ

| キー | 型 | 説明 |
|:-----|:---|:-----|
| `/Type` | 名前 | `/XObject` |
| `/Subtype` | 名前 | `/Image` |
| `/Width` | 整数 | 画像の幅（ピクセル） |
| `/Height` | 整数 | 画像の高さ（ピクセル） |
| `/ColorSpace` | 名前 or 配列 | 色空間（`/DeviceRGB`、`/DeviceGray` など） |
| `/BitsPerComponent` | 整数 | 1コンポーネントあたりのビット数（1, 2, 4, 8, 16） |
| `/Filter` | 名前 or 配列 | 圧縮フィルタ（`/DCTDecode` = JPEG など） |
| `/SMask` | ストリーム | ソフトマスク（アルファチャンネル） |
| `/Mask` | ストリーム or 配列 | ハードマスクまたはカラーキーマスク |
| `/ImageMask` | 真偽値 | 描画色で塗るステンシル画像の指定。省略時は false |

#### Form XObject の主要エントリ

| キー | 型 | 説明 |
|:-----|:---|:-----|
| `/Type` | 名前 | `/XObject` |
| `/Subtype` | 名前 | `/Form` |
| `/BBox` | 配列 | バウンディングボックス `[llx lly urx ury]` |
| `/Matrix` | 配列 | フォーム空間からユーザー空間への変換行列（デフォルト: 単位行列） |
| `/Resources` | 辞書 | フォーム内で使用されるリソース（独自のスコープ） |

#### コンテンツストリームでの使用例
```
q                     % グラフィックスステート保存
100 0 0 100 50 700 cm % 変換行列設定（位置・サイズ指定）
/Im0 Do               % XObject "Im0" を描画
Q                     % グラフィックスステート復元
```

#### pdfmod の取得・回復方針

- `PdfResources.getXObject` は現在のスコープで名前を引き、ストリームの未復号バイトを保持する。名前やストリームがないときは未解決、参照先の解析エラーはそのまま返す。
- ストリームがあれば、種別が欠落・不正・未知でも取得できる。未知の名前は元の綴りを保持し、非推奨の `/PS` は独立した種別にする。
- 不正な画像属性や `/BBox` はその属性だけ未設定にする。矩形は対角2点を正規化し、不正な `/Matrix` は省略時と同じ単位行列に回復する。

### 3.3 /ExtGState（拡張グラフィックスステート辞書）

単一のオペレータでは表現できない複雑な描画状態を辞書として定義する。

```
/ExtGState << /GS1 10 0 R >>
```

#### 拡張グラフィックスステートの主要エントリ

| キー | 型 | 説明 | デフォルト |
|:-----|:---|:-----|:-----------|
| `/Type` | 名前 | `/ExtGState` | - |
| `/LW` | 実数 | 線の太さ | 1.0 |
| `/LC` | 整数 | 線端の形状（0=Butt, 1=Round, 2=Square） | 0 |
| `/LJ` | 整数 | 線接合の形状（0=Miter, 1=Round, 2=Bevel） | 0 |
| `/ML` | 実数 | マイター限界値 | 10.0 |
| `/D` | 配列 | 破線パターン `[[dash_array] phase]` | `[[] 0]` |
| `/RI` | 名前 | レンダリングインテント | `/RelativeColorimetric` |
| `/OP` | ブール | ストロークのオーバープリント | false |
| `/op` | ブール | フィルのオーバープリント | false |
| `/OPM` | 整数 | オーバープリントモード | 0 |
| `/Font` | 配列 | `[font_ref size]` フォントとサイズ | - |
| `/ca` | 実数 | フィルの不透明度（0.0〜1.0） | 1.0 |
| `/CA` | 実数 | ストロークの不透明度（0.0〜1.0） | 1.0 |
| `/BM` | 名前 or 配列 | ブレンドモード | `/Normal` |
| `/SMask` | 辞書 or 名前 | ソフトマスク辞書 or `/None` | `/None` |
| `/AIS` | ブール | アルファソースフラグ | false |
| `/TK` | ブール | テキストノックアウトフラグ | true |

#### ブレンドモード一覧

| 名前 | 説明 |
|:-----|:-----|
| `/Normal` | 通常（デフォルト） |
| `/Multiply` | 乗算 |
| `/Screen` | スクリーン |
| `/Overlay` | オーバーレイ |
| `/Darken` | 比較（暗） |
| `/Lighten` | 比較（明） |
| `/ColorDodge` | 覆い焼きカラー |
| `/ColorBurn` | 焼き込みカラー |
| `/HardLight` | ハードライト |
| `/SoftLight` | ソフトライト |
| `/Difference` | 差の絶対値 |
| `/Exclusion` | 除外 |

#### コンテンツストリームでの使用例
```
/GS1 gs               % 拡張グラフィックスステート "GS1" を適用
```

#### pdfmod の適用・回復方針

- 同期インタプリタの実行前に `ExtGStateResources.fromResources` で現在のスコープのカテゴリを解決し、`OperatorRegistry.createDefault` または `registerGraphicsStateOperators` へ渡す。スコープを跨いで結果を共有しない。
- `/ExtGState`、各辞書、対応パラメータの値と配列要素の間接参照を解決する。カテゴリの解決エラーは準備時に返し、各名前のエラーはその名前の `gs` 実行時に返す。
- `/LW /LC /LJ /ML /D /CA /ca /BM /SMask /Font` を適用する。省略キーは現在値を保持し、専用命令と同じ `GraphicsState.update` / `TextState.withFont` で更新する。
- `/Font` は `[フォント辞書の参照 サイズ]` を読む。直接辞書も受理する。`Tf` の名前指定と辞書指定は同一のフォント選択の別バリアントとして保持し、後の指定が前の指定を置き換える。`fontName` はこの選択から導出する。
- `/BM` の名前配列は最初の対応モードを選び、対応モードがない配列は `Normal` にする。`Compatible` は `Normal` として扱う。標準の非分離モード `Hue /Saturation /Color /Luminosity` も状態として保持する。
- `/SMask` は `/None` または辞書を保持する。辞書内部の検証・透明グループ描画・ピクセル合成は別の処理であり、ここでは行わない。
- 未知・未対応のキーは `EXT_GSTATE_UNSUPPORTED_ENTRY`、不正な型・不透明度の範囲外などは `EXT_GSTATE_INVALID_ENTRY` を報告し、そのキーだけ無視して続ける。`/Type` は描画パラメータではないため読み飛ばす。
- 名前や辞書がない場合は `EXT_GSTATE_NOT_FOUND` を報告して状態を保持する。警告位置は適用した `gs` のバイト位置とする。参照解決エラーは警告へ置き換えず伝播する。
- 線幅・マイター・破線の値域検証は、既存専用オペレータと同様に対象外。今回の読み取りでは有限の数値だけを受理する。
- 透明度の初期値は輪郭・塗りとも1、ブレンドモードは `Normal`、ソフトマスクは `/None`。これらとフォント選択も `q` / `Q` による保存・復元の対象とする。

### 3.4 /ColorSpace（色空間辞書）

デバイス非依存の色空間定義をマッピングする。

```
/ColorSpace << /CS1 [/ICCBased 11 0 R]
               /CS2 [/Indexed /DeviceRGB 255 12 0 R]
            >>
```

#### 色空間の種類

| カテゴリ | 色空間名 | 説明 |
|:---------|:---------|:-----|
| デバイス依存 | `/DeviceGray` | グレースケール（1コンポーネント） |
| デバイス依存 | `/DeviceRGB` | RGB色空間（3コンポーネント） |
| デバイス依存 | `/DeviceCMYK` | CMYK色空間（4コンポーネント） |
| CIEベース | `/CalGray` | キャリブレーテッドグレースケール |
| CIEベース | `/CalRGB` | キャリブレーテッドRGB |
| CIEベース | `/Lab` | CIE L*a*b*色空間 |
| CIEベース | `/ICCBased` | ICCプロファイルに基づく色空間 |
| 特殊 | `/Indexed` | インデックスカラー（パレット）色空間 |
| 特殊 | `/Pattern` | パターン色空間 |
| 特殊 | `/Separation` | 特色（スポットカラー） |
| 特殊 | `/DeviceN` | 複数の特色を組み合わせた色空間 |

#### 成分数とコンテンツストリームでの選択

| 色空間 | 数値成分数 |
|:-------|:-----------|
| DeviceGray / CalGray / Separation / Indexed | 1 |
| DeviceRGB / CalRGB / Lab | 3 |
| DeviceCMYK | 4 |
| ICCBased | プロファイルストリームの `/N`（1・3・4） |
| DeviceN | 色材名の配列の長さ |
| Pattern | 着色パターンは0、非着色パターンは基底色空間の成分数。パターン名は別に必要 |

- `cs` は塗り、`CS` は輪郭の色空間を選択し、その色空間の初期色に切り替える。デバイス色は黒、Separation / DeviceN は全成分1、ほかの数値成分は0を初期値とする。Labの成分範囲へのクリップはこの解決層では扱わない。
- `sc` / `SC` / `scn` / `SCN` は現在の色空間に必要な数の数値成分を受け取る。Pattern は `scn` / `SCN` を使い、数値成分の後ろにパターン名を指定する。
- `Indexed` の基底がRGBでも、オペランドはRGB値3個ではなくパレットの添字1個。基底色空間の定義は別途解決して保持する。

#### pdfmod の準備・回復方針

- 同期インタプリタの実行前に `ColorSpaceResources.fromResources(resources, resolveRef)` で現在のスコープを解決し、`OperatorRegistry.createDefault(extGStates, colorSpaces)` または `registerColorOperators(registry, colorSpaces)` へ渡す。
- `/Resources` 自体の継承・間接参照解決は既存のページ属性解決を使う。色空間の準備では `/ColorSpace` カテゴリ・各定義・配列の族名・ICCBasedプロファイルと `/N`・DeviceN名前配列と各名前・Indexed / Pattern基底の間接参照を解決する。CIE色空間のパラメータ辞書も解決する。
- カテゴリの参照解決エラーは準備時に返す。個別定義のエラーは保持し、その名前を `cs` / `CS` で選択するときに原因をそのまま返す。同名でも別のページ・フォームのスコープと共有しない。
- 色空間配列の先頭にある未知の族は `COLOR_SPACE_UNSUPPORTED`、成分数を確定するための値の不正・欠落や循環は `COLOR_SPACE_INVALID` を報告する。不在の名前は、`cs` / `CS` で直接指定した場合も、定義内の別名や基底色空間から参照した場合も `COLOR_SPACE_NOT_FOUND` とする。いずれも選択した命令の位置で報告する。再帰は32段を上限とし、上限でも不明な定義として回復する。
- 不明な色空間は以前の成分数を引き継がず、成分数不明として保持する。その後の色命令は数値型を検証して保持するが、個数の一致は検証しない。Indexed は基底が不明でも添字は1成分である。
- 既知の成分数の過不足は `OPERATOR_OPERAND_COUNT_MISMATCH`、型の不一致は `OPERATOR_OPERAND_TYPE_MISMATCH`。Pattern に `sc` / `SC` を使う場合は `OPERATOR_ILLEGAL_STATE` を返す。
- 色空間と色値は `q` / `Q` の保存・復元対象。ここで扱うのは族・成分数・色値の保持までであり、ICCプロファイル変換、CIEパラメータの数値検証、パレット展開、特色の関数評価、パターンの描画は後段の処理とする。パターンの取得は次節の描画リソースの準備が担当する。

### 3.5 /Pattern（パターン辞書）

タイリングパターンやシェーディングパターンを定義する。

| パターンタイプ | 値 | 説明 |
|:---------------|:---|:-----|
| タイリングパターン | 1 | 繰り返し描画される小さな図形の定義 |
| シェーディングパターン | 2 | グラデーション等のスムーズな色変化 |

#### 主要属性と名前オペランド

- 種別1はストリームを持ち、`/PaintType`（1＝着色、2＝非着色）、`/TilingType`（1〜3）、`/BBox`（4数値）、`/XStep`・`/YStep`（有限・0以外）、`/Resources`（辞書）を読む。`/Matrix` は6数値で、省略時は単位行列を使う。未復号のセルストリームを保持し、内部の命令は実行しない。
- 種別2は `/Shading` を解決して次節の型へ変換し、`/Matrix` と任意の `/ExtGState` 辞書を保持する。拡張状態の適用は行わない。
- `scn` / `SCN` の名前オペランドは、現在の色空間が Pattern の場合だけ許可する。名前から現在の `/Pattern` サブ辞書を引く。Pattern以外では数値オペランドとして型・個数を検証し、名前を受理しない。
- 着色タイリングとシェーディングパターンは基底色空間を伴わない Pattern、非着色タイリングは基底を伴う Pattern と組み合わせる。異なる組み合わせは `OPERATOR_ILLEGAL_STATE`。数値成分数は基底の成分数に従い、名前は数えない。
- 名前と数値成分は従来どおり色状態へ保存する。取得した型付き定義は `PaintResources.patterns` で参照できる。実際のパターン描画は行わない。

### 3.6 /Shading（シェーディング辞書）

グラデーション描画を定義する。

| シェーディングタイプ | 値 | 説明 |
|:---------------------|:---|:-----|
| 関数ベース | 1 | 2D関数による色定義 |
| 軸方向 | 2 | 2点間の線形グラデーション |
| 放射状 | 3 | 2つの円間の放射グラデーション |
| フリーフォームメッシュ | 4 | 自由形式のメッシュグラデーション |
| ラティスフォームメッシュ | 5 | 格子形式のメッシュグラデーション |
| クーンズパッチメッシュ | 6 | クーンズパッチによるメッシュ |
| テンソル積パッチメッシュ | 7 | テンソル積パッチによるメッシュ |

#### 共通属性と sh

- `/ColorSpace` を名前または配列として取得し、任意の `/Background` を数値配列、`/BBox` を4数値として読む。色空間配列の内部の解釈、背景の成分数やシェーディング固有の必須キー・値域の全面検証は後段が担当する。
- 種別4〜7はメッシュの未復号ストリームを必須とする。種別番号は1〜7に閉じ、未知の番号は元のオブジェクトを持つ Unknown とする。
- `/Function` は元の `PdfValue` のまま保持する。間接参照を解決せず、関数辞書・配列の内部も評価しない。
- `sh` は名前オペランドを正確に1個受け取り、現在の `/Shading` サブ辞書を引く。既定のレジストリにも登録する。色・色空間・パス・クリップを変更せず、この段階では描画しない。

#### pdfmod の描画リソースの準備・回復方針

- 同期実行前に `PaintResources.fromResources(resources, resolveRef)` で Pattern / Shading のカテゴリ・各定義・主要属性を間接参照も含めて解決する。数値配列は各要素も解決する。別のページ・フォームの同名定義へフォールバックしない。
- 解決結果は `OperatorRegistry.createDefault(extGStates, colorSpaces, paints)`、または色命令に限れば `registerColorOperators(registry, colorSpaces, paints)` へ渡す。
- カテゴリの参照解決エラーは準備時に返す。各定義・主要属性の参照エラーは名前別に保持し、実際にその名前を使う `scn` / `SCN` / `sh` で元の原因を返す。参照先が存在せずリゾルバがPDFのnullを返した場合は、解決エラーとせず不正な定義として扱う。
- 不在の名前は `PATTERN_NOT_FOUND` / `SHADING_NOT_FOUND`。未知・欠落・不正な型の種別番号は `PATTERN_UNSUPPORTED` / `SHADING_UNSUPPORTED`、既知種別の主要属性が不正なら `PATTERN_INVALID` / `SHADING_INVALID`。警告は命令の位置で報告し後続命令を処理する。不正なMatrixを単位行列へ置き換える回復はしない。
- 名前不在・Unknownのパターンでも指定名と数値成分は色状態へ保存する。警告による回復はpdfmod独自の方針であり、未知の定義が描画可能であることを意味しない。

### 3.7 /ProcSet（手続きセット配列）

```
/ProcSet [/PDF /Text /ImageB /ImageC /ImageI]
```

| 名前 | 説明 |
|:-----|:-----|
| `/PDF` | PDF基本描画オペレータ |
| `/Text` | テキスト描画オペレータ |
| `/ImageB` | モノクロ画像オペレータ |
| `/ImageC` | カラー画像オペレータ |
| `/ImageI` | インデックスカラー画像オペレータ |

**注意**: モダンなPDFプロセッサでは実質的に無視されるが、仕様上の互換性のために生成時に含めることが推奨される。

## 4. グラフィックスステートマシン

### 4.1 ステートの構成要素

ライブラリが管理すべきグラフィックスステートの完全な一覧。

| パラメータ | デフォルト値 | 設定方法 |
|:-----------|:-------------|:---------|
| CTM（カレント変換行列） | 単位行列 | `cm` オペレータ |

| 線の太さ | 1.0 | `w` オペレータ |
| 線端の形状 | 0 (Butt) | `J` オペレータ |
| 線接合の形状 | 0 (Miter) | `j` オペレータ |
| マイター限界値 | 10.0 | `M` オペレータ |
| 破線パターン | 実線 | `d` オペレータ |
| レンダリングインテント | RelativeColorimetric | `ri` オペレータ |
| フラットネス許容値 | 1.0 | `i` オペレータ |

### 4.2 テキストステート

テキスト描画に関する追加のステートパラメータ。

| パラメータ | デフォルト値 | 設定オペレータ | 説明 |
|:-----------|:-------------|:---------------|:-----|
| 文字間隔 | 0 | `Tc` | 文字間の追加スペース |
| 単語間隔 | 0 | `Tw` | 単語間の追加スペース（スペース文字のみに適用） |
| 水平スケーリング | 100 | `Tz` | テキストの水平方向の拡大率（%） |

#### テキストレンダリングモード

| 値 | 説明 |
|:---|:-----|
| 0 | フィル（塗りつぶし） |

| 4 | フィル＋クリッピングパスに追加 |
| 5 | ストローク＋クリッピングパスに追加 |

### 4.3 ステートスタックの実装

```
struct GraphicsState {
    ctm: Matrix,
    clipping_path: Path,
    stroke_color_space: ColorSpace,
    fill_color_space: ColorSpace,
    stroke_color: Color,
    fill_color: Color,
    line_width: f64,
    line_cap: LineCap,
    line_join: LineJoin,
    miter_limit: f64,
    dash_pattern: DashPattern,
    rendering_intent: RenderingIntent,
    flatness: f64,
    // テキストステート
    char_spacing: f64,
    word_spacing: f64,
    horizontal_scaling: f64,
    text_leading: f64,
    text_font: Option<Font>,
    text_font_size: f64,
    text_rendering_mode: TextRenderingMode,
    text_rise: f64,
    // 透明度関連
    stroke_alpha: f64,
    fill_alpha: f64,
    blend_mode: BlendMode,
    soft_mask: Option<SoftMask>,
}

struct GraphicsStateStack {
    stack: Vec<GraphicsState>,
    current: GraphicsState,
}

impl GraphicsStateStack {
    fn save(&mut self) {         // q オペレータ
        self.stack.push(self.current.clone());
    }

    fn restore(&mut self) {      // Q オペレータ
        if let Some(state) = self.stack.pop() {
            self.current = state;
        }
    }
}
```
