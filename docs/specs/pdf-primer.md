## 1. PDFファイルの全体像

### 1.1 4つのセグメント

PDF ファイルは物理的に 4 つのセグメントで構成されます。

```text
+-----------------------------+
| Header                      |  %PDF-1.7（バージョン宣言）
+-----------------------------+
| Body                        |  オブジェクトの集合体
|   1 0 obj ... endobj        |  （ページ、フォント、画像など）
|   2 0 obj ... endobj        |
|   ...                       |
+-----------------------------+
| XRef Table                  |  各オブジェクトのバイト位置を記録した索引
+-----------------------------+
| Trailer + startxref + %%EOF |  ドキュメントのエントリーポイント
+-----------------------------+
```

### 1.2 末尾から読む — PDFの最大の特徴

PDF は**ファイル末尾から逆方向に解析を開始**します。先頭から順に読むのではありません。

```text
解析の流れ:

  1. ファイル末尾の %%EOF を見つける
  2. その上の startxref から XRef テーブルのオフセットを得る
  3. XRef テーブルで全オブジェクトの位置を把握する
  4. Trailer 辞書の /Root からドキュメント全体にアクセスする
```

この設計により、PDF はファイル全体を読み込まなくても特定のページだけを高速に表示できます。

### 1.3 座標系

PDF の座標原点は**左下**です（数学の直交座標系と同じ）。既定の 1 単位は 1/72 インチ（= 1 PostScript ポイント）です。

```text
(0, 792) ─────────── (612, 792)
    |                      |
    |    Letterサイズの例    |
    |    612 × 792 pt      |
    |   (8.5 × 11 インチ)   |
(0, 0) ───────────── (612, 0)
  原点
```

> 参考: A4 サイズは `[0 0 595.276 841.89]`（210 × 297 mm）です。

## 2. PDFオブジェクト — 9つの基本データ型

PDF には 9 種類のプリミティブデータ型があります（ISO 32000 §7.3）。  
pdfmod では `PdfObject` 共用体型としてこれらを表現します。

### 2.1 一覧

| # | 型名 | PDF 内の記述例 | 説明 | `PdfObject` の `type` |
| :--- | :--- | :--- | :--- | :--- |
| 1 | Null | `null` | 値が存在しないことを示す | `"null"` |
| 2 | Boolean | `true` / `false` | 論理値 | `"boolean"` |
| 3 | Integer | `42` / `-3` | 整数値 | `"integer"` |
| 4 | Real | `3.14` / `-0.5` | 浮動小数点数 | `"real"` |
| 5 | String | `(Hello)` / `<48656C6C6F>` | 文字列 | `"string"` |
| 6 | Name | `/Type` / `/Pages` | 識別子（辞書のキーなど） | `"name"` |
| 7 | Array | `[1 2 3]` | 順序付きリスト | `"array"` |
| 8 | Dictionary | `<< /Key /Value >>` | キー → 値のマップ | `"dictionary"` |
| 9 | Stream | `<< /Length 44 >> stream ... endstream` | 辞書 + バイナリデータ | `"stream"` |

### 2.2 各型の詳細

#### Null

```pdf
null
```

「値がない」ことを明示的に表す型です。解決できない間接参照の結果としても返されます。

#### Boolean

```pdf
true
false
```

大文字・小文字を区別します（`True` や `FALSE` は無効）。

#### Integer / Real

```pdf
42      % Integer
-3      % Integer
3.14    % Real
-.002   % Real
```

PDF には「数値」という単一型はなく、小数点の有無で整数（Integer）と実数（Real）を区別します。

#### String

文字列には 2 つの表記方法があります。

```pdf
(Hello World)        % リテラル文字列（丸括弧で囲む）
<48656C6C6F>         % 16進文字列（山括弧で囲む）
```

内部的にはバイト列として保持します。描画用テキストの意味（Unicode）を取り出すには別途 `/ToUnicode` CMap が必要です。  
リテラル文字列は `\n`（改行）、`\(`（エスケープされた括弧）、`\053`（8進数）などのエスケープシーケンスを含むことがあります。

#### Name

```pdf
/Type
/Pages
/Font
```

`/` で始まる識別子です。辞書のキーとして使われるほか、値としても使われます（例: `/Type /Catalog` の `/Catalog` は値）。

#### Array

```pdf
[1 2.5 (text) /Name [nested array]]
```

任意の `PdfObject` を要素に持てる順序付きリストです。異なる型を混在できます。

#### Dictionary

```pdf
<< /Type /Catalog
   /Pages 2 0 R
   /Version /1.7
>>
```

Name をキー、任意の `PdfObject` を値とするマップです。ページ・フォント・画像など、PDF のほぼすべての構造が辞書で表現されます。

#### Stream

```pdf
4 0 obj
<< /Length 44
   /Filter /FlateDecode
>>
stream
BT /F1 24 Tf 72 720 Td (Hello World) Tj ET
endstream
endobj
```

辞書（メタデータ）とバイナリデータの組み合わせです。ページの描画命令、画像データ、フォントデータ、さらに XRef テーブル（PDF 1.5+）もストリームで格納されます。  
`/Filter` で圧縮形式を指定し、最も一般的なのは `/FlateDecode`（zlib 圧縮）です。

## 3. 間接参照 — オブジェクト同士を繋ぐポインタ

### 3.1 仕組み

PDF のオブジェクトは**間接オブジェクト**として定義され、他のオブジェクトから**間接参照**で指し示されます。

```pdf
% 定義側（Body内）: オブジェクト番号2、世代番号0
2 0 obj
<< /Type /Pages ... >>
endobj

% 参照側（別のオブジェクト内）: 「2 0 R」= オブジェクト2・世代0を参照
<< /Pages 2 0 R >>
```

`N G R` の 3 つのトークンで構成されます。

- **N**: オブジェクト番号（1 以上の正の整数）
- **G**: 世代番号（オブジェクトの再利用回数、通常は `0`）
- **R**: 参照を示すキーワード

### 3.2 世代番号とは

オブジェクトが削除されて同じ番号で再利用されると、世代番号がインクリメントされます。実務的にはほとんどの PDF で世代番号は `0` です。

### 3.3 pdfmod での表現

pdfmod では間接参照（`IndirectRef`）を `PdfObject` の 1 バリアントとして、次の 2 フィールドの組で表現します。

| フィールド | 型 | 説明 |
| :--- | :--- | :--- |
| `objectNumber` | 整数 | オブジェクト番号（`N G R` の `N`） |
| `generationNumber` | 整数 | 世代番号（`N G R` の `G`、通常は `0`） |

オブジェクト識別子（`ObjectId`）も同じ 2 フィールドの組を指します。  
`ObjectResolver`（TypeScript 実装では `ObjectStore`）が間接参照を実体の `PdfObject` へ解決します。

## 4. XRefテーブル — オブジェクトの住所録

### 4.1 役割

XRef（Cross-Reference）テーブルは **「オブジェクト番号 → ファイル内の位置」を記録した索引**です。  
リーダーは目的のオブジェクトを読むとき、XRef テーブルからバイトオフセットを引いて直接シークするため、巨大な PDF でも必要な箇所だけを高速に読み込めます。

### 4.2 テキスト形式（従来形式、PDF 1.4以前）

```pdf
xref
0 6                            % オブジェクト0から6個のエントリ
0000000000 65535 f             % オブジェクト0: 空きエントリ (f = free)
0000000009 00000 n             % オブジェクト1: バイトオフセット9 (n = in-use)
0000000058 00000 n             % オブジェクト2: バイトオフセット58
0000000115 00000 n             % オブジェクト3: バイトオフセット115
0000000206 00000 n
0000000300 00000 n
```

各エントリは規格上 **20 バイト固定長**です。

```text
nnnnnnnnnn ggggg s EOL
|          |     |  |
|          |     |  +-- 行末 (CR+LF 等で2バイト)
|          |     +----- 状態フラグ: n=使用中, f=空き
|          +----------- 世代番号 (5桁、0埋め)
+---------------------- バイトオフセット または 次の空きオブジェクト番号 (10桁、0埋め)
```

### 4.3 ストリーム形式（PDF 1.5+）

PDF 1.5 からは、XRef テーブルをバイナリのストリームオブジェクトとして格納できます。圧縮効率が高く、**オブジェクトストリーム（`type=2`）**にも対応します。

```pdf
15 0 obj
<< /Type /XRef
   /Size 20
   /W [1 3 1]           % 各フィールドのバイト幅: type=1B, field2=3B, field3=1B
   /Root 1 0 R
   /Filter /FlateDecode
>>
stream
... (Flate圧縮されたバイナリデータ) ...
endstream
endobj
```

### 4.4 XRefEntry の 3 つのタイプ

ストリーム形式では、各エントリは 3 つのフィールド（`type`, `field2`, `field3`）で構成されます。

| `type` | 意味 | `field2` | `field3` |
| :--- | :--- | :--- | :--- |
| **0** | 空きエントリ（削除済み） | 次の空きオブジェクト番号 | 再利用時の世代番号 |
| **1** | 通常のオブジェクト | ファイル内バイトオフセット | 世代番号 |
| **2** | オブジェクトストリーム内 | 親ストリームのオブジェクト番号 | ストリーム内インデックス |

pdfmod ではテキスト形式もこの 3 種に正規化して `XRefEntry` 型で統一管理します。

### 4.5 オブジェクトストリーム（`type=2`）

PDF 1.5 で導入された仕組みで、複数の小さなオブジェクトを **1 つのストリームにまとめて圧縮**します。

```text
通常:                          オブジェクトストリーム:
  1 0 obj ... endobj            10 0 obj
  2 0 obj ... endobj            << /Type /ObjStm /N 3 /First 15 >>
  3 0 obj ... endobj            stream
                                1 0 2 10 3 20    ← ヘッダ（番号 オフセット のペア）
                                << /Type /Page >> ← オブジェクト1の中身
                                [1 2 3]           ← オブジェクト2の中身
                                (text)            ← オブジェクト3の中身
                                endstream
                                endobj
```

`XRefEntry` の `type=2` がこの形式を指します。`field2` が親ストリームのオブジェクト番号、`field3` がストリーム内のインデックスです。

### 4.6 XRefTable

マージ済みの XRef テーブル全体を表す型です。

| フィールド | 型 | 説明 |
| :--- | :--- | :--- |
| `entries` | オブジェクト番号 → `XRefEntry` のマップ | 各オブジェクトのエントリ |
| `size` | 整数 | 最大オブジェクト番号 + 1 |

## 5. トレイラ辞書 — ドキュメントへの入口

### 5.1 役割

トレイラ辞書は PDF 解析の**起点**です。ここから `/Root`（ドキュメントカタログ）を辿ることで、全ページ・全リソースへアクセスします。

### 5.2 テキスト形式のトレイラ

```pdf
trailer
<< /Size 6
   /Root 1 0 R
   /Info 5 0 R
   /ID [<abc123def456> <abc123def456>]
>>
startxref
408
%%EOF
```

### 5.3 主要エントリ

| キー | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| `/Root` | 間接参照 | **必須** | ドキュメントカタログへの参照（ドキュメント全体のルート） |
| `/Size` | 整数 | **必須** | XRef テーブルのエントリ総数（最大オブジェクト番号 + 1） |
| `/Prev` | 整数 | 条件付き | 前の XRef テーブルのバイトオフセット |
| `/Info` | 間接参照 | 任意 | ドキュメント情報辞書（作成者、タイトルなど） |
| `/ID` | 配列 | 条件付き | ファイル識別子 `[永続ID, 変更ID]` |

### 5.4 pdfmod での表現

トレイラ辞書は `TrailerDict` 型で表現します。`root` と `size` は必須、それ以外は省略可能です。

| フィールド | 型 | 説明 |
| :--- | :--- | :--- |
| `root` | 間接参照 | `/Root`（必須） |
| `size` | 整数 | `/Size`（必須） |
| `prev` | バイトオフセット | `/Prev` — 前の XRef テーブルのバイトオフセット（任意） |
| `info` | 間接参照 | `/Info`（任意） |
| `id` | バイト列 2 要素の組 `[永続ID, 変更ID]` | `/ID`（任意） |
| `encrypt` | 辞書または間接参照 | `/Encrypt` — 暗号化辞書（任意） |
| `xrefStm` | バイトオフセット | `/XRefStm` — ハイブリッド参照ファイルの相互参照ストリーム位置。テキスト形式トレイラのみ（任意） |

## 6. インクリメンタルアップデート — PDFの編集方法

### 6.1 仕組み

PDF は編集時に**元のバイト列を変更せず、ファイル末尾に変更差分だけを追記**します。

```text
+-----------------------------+
| 元のHeader                   |
| 元のBody                     |
| 元のXRef                     |
| 元のTrailer (/Size 10)       |
+-----------------------------+ ← 元のファイルここまで
| 追加・変更されたオブジェクト    | ← 1回目の編集で追記
| 新しいXRef                   |
| 新しいTrailer                |
|   /Prev 408  ← 前のXRefを指す |
+-----------------------------+
| さらに追加されたオブジェクト    | ← 2回目の編集で追記
| 最新のXRef                   |
| 最新のTrailer                |
|   /Prev 1024 ← 1回目を指す   |
+-----------------------------+
```

### 6.2 /Prev チェーンと XRef マージ

最新トレイラの `/Prev` を辿ると前の XRef テーブルへ到達します。これを再帰的に辿り、**新しいエントリが古いエントリを上書きする形でマージ**します。

```text
最新XRef (優先度: 高)
    ↓ /Prev
1回目XRef (優先度: 中)
    ↓ /Prev
元のXRef (優先度: 低)
    ↓
マージ済み XRefTable
```

同じオブジェクト番号が複数の XRef に現れる場合、最新のものが有効になります。

## 7. 全体の解析フロー

```text
PDFバイナリ (バイト列)
    │
    ▼
[1] %%EOF を末尾から検索
    │
    ▼
[2] startxref の値を取得（XRef テーブルのオフセット）
    │
    ▼
[3] XRef テーブルを解析
    │  テキスト形式 / ストリーム形式を自動判定
    │
    ▼
[4] Trailer 辞書を解析
    │  /Prev があれば [3] に戻って再帰的にマージ
    │
    ▼
[5] マージ済み XRefTable + TrailerDict が完成
    │
    ▼
[6] ObjectResolver（TS 実装は ObjectStore）で /Root を解決
    │  間接参照 → XRef からオフセット取得 → パース → LRU キャッシュ
    │
    ▼
[7] ドキュメントカタログ → ページツリー → 各ページ
    │
    ▼
PdfDocument / PdfPage
```

`@pdfmod/core`（TypeScript）のモジュールとの対応は次のとおりです。

| ステップ | `@pdfmod/core` モジュール |
| :--- | :--- |
| `[1]`–`[2]` | `StartXRefScanner`（`xref/startxref/`） |
| `[3]` | `XRefTableParser`（`xref/table/`）/ `XRefStreamParser`（`xref/stream/`） |
| `[4]` | `TrailerParser`（`xref/trailer/`）/ `XRefMerger`（`xref/merger/`） |
| `[5]` | 型定義: `XRefTable`, `TrailerDict`（`pdf/types/`） |
| `[6]` | `ObjectStore`（`objects/object-store/`）+ `LRUCache`（`utils/lru-cache/`） |
| `[6]` | `ObjectParser`（`objects/object-parser/`） |
| `[7]` | ページツリー走査（`document/page-tree/`） |

> 各モジュールの詳細仕様は [docs/pdf-parsing-pipeline/](../pdf-parsing-pipeline/index.md) を参照してください。

## 8. 用語集

| 用語 | 説明 |
| :--- | :--- |
| **間接オブジェクト** | `N G obj ... endobj` で定義されるオブジェクト。番号で参照できる |
| **間接参照** | `N G R` 形式のポインタ。`ObjectResolver` が実体へ解決する |
| **オブジェクト番号** | オブジェクトを一意に識別する正の整数（1 以上） |
| **世代番号** | オブジェクトの再利用回数（通常 `0`。削除後の再利用でインクリメント） |
| **XRef** | Cross-Reference。オブジェクト番号 → ファイル内位置の索引 |
| **トレイラ** | ドキュメントのエントリーポイント。`/Root` から全体へアクセスする |
| **インクリメンタルアップデート** | ファイル末尾に差分を追記する編集方式 |
| **オブジェクトストリーム** | 複数のオブジェクトを 1 つのストリームにまとめる圧縮手法（PDF 1.5+） |
| **FlateDecode** | zlib 圧縮。PDF で最も一般的なストリーム圧縮フィルタ |
| **MediaBox** | ページの物理的なサイズを定義する矩形 `[llx lly urx ury]` |
| **CMap / ToUnicode** | 文字コード → Unicode 変換マップ。テキスト抽出に必要 |
| **RPN（逆ポーランド記法）** | コンテンツストリームの命令形式。`72 720 Td` = 座標 `(72, 720)` に移動 |
