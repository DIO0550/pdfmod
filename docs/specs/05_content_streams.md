## 1. 概要

PDF ページの視覚表現は、ページ辞書の `/Contents` が指す**コンテンツストリーム**内に記述された命令列によって決まります。構文は PostScript 由来の**後置記法（逆ポーランド記法: RPN）**です。

> **重要**: コンテンツストリームには**ループ（for / while）・条件分岐（if）・変数宣言は一切存在しません**。純粋に上から下へ実行される描画命令の列です。

### 1.1 PDF ファイル内での位置づけと実行の流れ

```text
PDF ファイル
  ├─ Header
  ├─ Body
  │   ├─ Catalog → Pages → Page
  │   │                      └─ /Contents ──→ コンテンツストリーム (本書の対象)
  │   └─ Font / Image / Resource オブジェクト
  ├─ XRef
  └─ Trailer
```

```pdf
% ページ辞書が /Contents でストリームを参照する例
3 0 obj
<< /Type /Page
   /Parent 2 0 R
   /MediaBox [0 0 612 792]
   /Resources << /Font << /F1 5 0 R >> >>
   /Contents 4 0 R
>>
endobj

4 0 obj
<< /Length 45 >>
stream
q
1 0 0 1 100 200 cm
10 20 m
200 20 l
S
Q
endstream
endobj
```

ストリーム展開後の命令列は、トークン単位で次のように処理されます。

```text
1. ストリームデータをデコード（圧縮解除）
2. バイト列をトークン化（オペランドとオペレータを識別）
3. オペランド（数値・文字列・名前・配列・辞書など）をスタックへプッシュ
4. オペレータが現れたら、スタックから必要なオペランドをポップして実行
```

たとえば `1 0 0 1 100 200 cm` は、6 つの数値オペランドを順にスタックへ積んだあと、`cm` オペレータへディスパッチされます。

### 1.2 pdfmod の実行パイプライン

`@pdfmod/core` では、コンテンツストリームの解釈を次の 3 層に分離しています。

```text
コンテンツストリーム (展開済みバイト列)
  │
  ▼
ContentStreamTokenizer
  ├─ 字句トークンをコンテンツストリーム向けトークン（オペレータ・インラインイメージ等）へ再分類
  │
  ▼
ContentStreamInterpreter
  ├─ プリミティブ・複合オペランド（配列 / 辞書）→ PdfObject として OperandStack へ積む
  ├─ インラインイメージ（BI ... ID ... EI）→ inlineImageHandler へ委譲
  ├─ オペレータ → OperatorRegistry からハンドラを検索して実行
  │     └─ 未登録オペレータの場合: 後続命令への混入を防ぐため OperandStack をクリア
  └─ EOF → 最終コンテキスト・警告一覧・画像描画一覧を返却
```

| 要素 | 責務と方針 |
| :--- | :--- |
| `ContentStreamTokenizer` | バイト列をトークン化し、キーワードをコンテンツストリームオペレータ・インラインイメージとして切り出す |
| `ContentStreamInterpreter` | RPN 実行ループ、配列・辞書オペランドの構築、`Do` による Form XObject の入れ子実行を統括する |
| `OperatorRegistry` | グラフィックスステート・パス・色・テキスト・XObject・シェーディング・マーク付きコンテンツの各ビルトインハンドラを管理する |
| 不正数値トークンの拒否 | `.`・`+`・`-` 単独のような妥当でない数値トークンは `OBJECT_PARSE_UNEXPECTED_TOKEN` として拒否し、ハンドラへ渡さない |

## 2. グラフィックスステートオペレータ

### 2.1 ステート管理

| オペレータ | オペランド | 説明 |
| :--- | :--- | :--- |
| `q` | なし | 現在のグラフィックスステートをスタックに保存 |
| `Q` | なし | スタックからグラフィックスステートを復元 |
| `cm` | `a b c d e f` | カレント変換行列（CTM）にアフィン変換行列を連結 |
| `w` | `lineWidth` | 線の太さを設定 |
| `J` | `lineCap` | 線端の形状（`0`: Butt, `1`: Round, `2`: Square） |
| `j` | `lineJoin` | 線接合の形状（`0`: Miter, `1`: Round, `2`: Bevel） |
| `M` | `miterLimit` | マイター限界値を設定 |
| `d` | `dashArray dashPhase` | 破線パターンを設定 |
| `ri` | `intent` | レンダリングインテントを設定 |
| `i` | `flatness` | フラットネス許容値を設定 |
| `gs` | `dictName` | 名前付き拡張グラフィックスステートを適用 |

### 2.2 一般的なイディオム: `q` / `Q` ペア

```pdf
q                        % ステート保存
  1 0 0 1 100 200 cm     % 座標変換（平行移動）
  /Im1 Do                % 画像を描画
Q                        % ステート復元（変換前の状態に戻る）
```

> `q` と `Q` は対応するペアで使います（任意の深さでネスト可能）。

## 3. 座標系とアフィン変換行列

### 3.1 PDF の座標系

```text
Y
^
|
|   ページの左下が原点 (0, 0)
|   X 軸は右方向に正
|   Y 軸は上方向に正
|
+---------> X
(0, 0)
```

- 既定のユーザー空間は**左下原点**（一般的な画面座標の左上原点とは上下が逆）。
- 既定の 1 ユーザー空間単位 = **1/72 インチ**（1 PostScript ポイント）。

### 3.2 アフィン変換行列

`cm` オペレータの 6 オペランド `a b c d e f` は次の $3 \times 3$ 行列を表します。

```text
| a  b  0 |
| c  d  0 |
| e  f  1 |
```

#### 基本的な変換パターン

| 変換 | `a` | `b` | `c` | `d` | `e` | `f` | 例 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 平行移動 | `1` | `0` | `0` | `1` | `tx` | `ty` | `1 0 0 1 100 200 cm` |
| 拡大縮小 | `sx` | `0` | `0` | `sy` | `0` | `0` | `2 0 0 2 0 0 cm` |
| 回転（$\theta$） | $\cos\theta$ | $\sin\theta$ | $-\sin\theta$ | $\cos\theta$ | `0` | `0` | `0 1 -1 0 0 0 cm`（90°） |
| せん断 | `1` | `shy` | `shx` | `1` | `0` | `0` | `1 0.5 0 1 0 0 cm` |

#### 行列の連結順序

$$\text{新 CTM} = \text{指定行列} \times \text{現在の CTM}$$

行列の乗算は非可換なため、適用順序が結果に影響します。

#### 画像配置の典型パターン

```pdf
q
width 0 0 height x y cm    % 画像の位置とサイズを指定
/Im0 Do                    % 1×1 の単位正方形から変換して描画
Q
```

## 4. パス構築オペレータ

PDF には円や多角形といった高レベル命令がなく、低レベルなパス（軌跡）構築オペレータで図形を組み立てたあと、ペイントオペレータで描画します。

### 4.1 パス構築

| オペレータ | オペランド | 説明 |
| :--- | :--- | :--- |
| `m` | `x y` | カレントポイントを `(x, y)` へ移動（新規サブパス開始） |
| `l` | `x y` | カレントポイントから `(x, y)` まで直線を追加 |
| `c` | `x1 y1 x2 y2 x3 y3` | 3 次ベジェ曲線（制御点 `(x1, y1)`, `(x2, y2)`、終点 `(x3, y3)`） |
| `v` | `x2 y2 x3 y3` | 3 次ベジェ曲線（最初の制御点がカレントポイント） |
| `y` | `x1 y1 x3 y3` | 3 次ベジェ曲線（2 つ目の制御点が終点と一致） |
| `h` | なし | 現在のサブパスを閉じる（始点へ直線を引く） |
| `re` | `x y width height` | 矩形サブパスを追加（唯一の高レベルプリミティブ） |

### 4.2 パス描画（ペイント）オペレータ

構築したパスを視覚化し、パスを消費します。

| オペレータ | 説明 |
| :--- | :--- |
| `S` | ストローク（パスに沿って線を描画） |
| `s` | パスを閉じてストローク（`h S` と等価） |
| `f` | フィル（非ゼロワインディング規則で塗りつぶし） |
| `F` | `f` と同義（互換性のため） |
| `f*` | フィル（偶奇規則で塗りつぶし） |
| `B` | フィル + ストローク（非ゼロワインディング規則） |
| `B*` | フィル + ストローク（偶奇規則） |
| `b` | パスを閉じてフィル + ストローク（非ゼロ） |
| `b*` | パスを閉じてフィル + ストローク（偶奇） |
| `n` | パスを描画せず消去（クリッピング設定後の終了処理に使用） |

### 4.3 クリッピングオペレータ

| オペレータ | 説明 |
| :--- | :--- |
| `W` | 非ゼロワインディング規則でクリッピングパスを設定 |
| `W*` | 偶奇規則でクリッピングパスを設定 |

> **注意**: `W` / `W*` 単体ではパスを消費しません。必ず直後にパスペイントオペレータ（描画不要なら `n`）を続けてクリッピングを確定させます。

```pdf
% 矩形でクリッピングする例
100 100 300 400 re   % 矩形パス構築
W n                  % クリッピング設定 + パス消去
% 以降の描画はこの矩形内に制限される
```

#### pdfmod の実装方針

確定したパス・内側判定規則（非ゼロ / 偶奇）・確定時点の CTM を、既存クリッピング領域との交差として保持します。以後の CTM 更新は確定済みクリップに影響せず、`Q` で保存時点の領域へ戻ります。

### 4.4 塗りつぶしルール

| ルール | 判定の仕組み（対象点から無限遠方へ半直線を引く） |
| :--- | :--- |
| **非ゼロワインディング規則**（Non-Zero Winding） | パスが左→右に横切れば `+1`、右→左なら `-1` を加算し、合計が **`0` 以外**なら内部（塗りつぶし対象） |
| **偶奇規則**（Even-Odd） | パスとの交差回数が**奇数**なら内部、**偶数**なら外部 |

### 4.5 実装例: 矩形の描画

```pdf
% 赤い塗り + 青い枠線（太さ 2pt）の矩形
q
1 0 0 rg               % フィル色を赤に設定
0 0 1 RG               % ストローク色を青に設定
2 w                    % 線の太さ 2pt
100 100 200 150 re     % 矩形パス (x=100, y=100, w=200, h=150)
B                      % フィル + ストローク
Q
```

### 4.6 実装例: 円の近似（ベジェ曲線）

PDF には円命令がないため、4 本の 3 次ベジェ曲線で近似します（近似係数 $k \approx 0.5522847498$）。

```text
中心 (cx, cy)、半径 r、k = 0.5522847498 の円:

  cx+r  cy      m                             % 右端から開始
  cx+r  cy+k*r  cx+k*r  cy+r  cx    cy+r  c   % 右上 → 上
  cx-k*r cy+r   cx-r    cy+k*r cx-r cy    c   % 上 → 左
  cx-r  cy-k*r  cx-k*r  cy-r  cx    cy-r  c   % 左 → 下
  cx+k*r cy-r   cx+r    cy-k*r cx+r cy    c   % 下 → 右（閉じる）
  S                                           % ストローク
```

## 5. 色指定オペレータ

ストローク色とフィル色は完全に独立して管理されます。**大文字 = ストローク、小文字 = フィル**という一貫した規則があります。

### 5.1 デバイス色空間オペレータ

| オペレータ | オペランド | 説明 |
| :--- | :--- | :--- |
| `G` / `g` | `gray` | DeviceGray のストローク / フィル色（`0`=黒, `1`=白） |
| `RG` / `rg` | `r g b` | DeviceRGB のストローク / フィル色（各 `0.0`〜`1.0`） |
| `K` / `k` | `c m y k` | DeviceCMYK のストローク / フィル色（各 `0.0`〜`1.0`） |

### 5.2 汎用色空間オペレータ

| オペレータ | オペランド | 説明 |
| :--- | :--- | :--- |
| `CS` / `cs` | `name` | ストローク / フィルの色空間を設定 |
| `SC` / `sc` | `c1 ... cn` | 現在の色空間に応じた成分数でストローク / フィル色を設定 |
| `SCN` / `scn` | `c1 ... cn [name]` | パターンや特殊色空間にも対応するストローク / フィル色設定 |

## 6. テキスト描画オペレータ

### 6.1 テキストブロック

テキスト命令は必ず `BT`（Begin Text）と `ET`（End Text）で囲みます。

```pdf
BT
  /F1 12 Tf              % フォント /F1、サイズ 12pt
  1 0 0 1 72 720 Tm      % テキスト行列設定（座標 (72, 720)）
  (Hello World) Tj       % 文字列描画
ET
```

### 6.2 テキスト状態オペレータ

| オペレータ | オペランド | 説明 |
| :--- | :--- | :--- |
| `Tc` | `charSpace` | 文字間隔（追加スペース） |
| `Tw` | `wordSpace` | 単語間隔（スペース文字のみ適用） |
| `Tz` | `scale` | 水平スケーリング（% 指定、`100`=等倍） |
| `TL` | `leading` | 行間隔（テキストリーディング） |
| `Tf` | `font size` | フォントとサイズを設定 |
| `Tr` | `render` | テキストレンダリングモード（`0`〜`7`） |
| `Ts` | `rise` | テキストライズ（上付き・下付き用の垂直オフセット） |

### 6.3 テキスト位置決めオペレータ

| オペレータ | オペランド | 説明 |
| :--- | :--- | :--- |
| `Td` | `tx ty` | 現在行の開始位置から相対移動 |
| `TD` | `tx ty` | `Td` に加え、`-ty TL` で行間隔も設定 |
| `Tm` | `a b c d e f` | テキスト行列と行行列を直接設定（絶対位置指定） |
| `T*` | なし | 次の行へ移動（`0 -TL Td` と等価） |

### 6.4 テキスト描画オペレータ

| オペレータ | オペランド | 説明 |
| :--- | :--- | :--- |
| `Tj` | `string` | 文字列を描画 |
| `TJ` | `array` | 文字列と位置調整値の配列を描画（§6.5） |
| `'` | `string` | 改行して文字列を描画（`T* string Tj` と等価） |
| `"` | `aw ac string` | 単語間隔 `aw`・文字間隔 `ac` を設定し、改行して文字列を描画 |

### 6.5 `TJ` オペレータの詳細

`TJ` は精密なカーニングや文字間調整に使われる配列ベースのテキスト描画オペレータです。

```pdf
[(H) 40 (ello) -20 ( W) 80 (orld)] TJ
```

配列要素を先頭から順に処理します。

| 要素の型 | 動作 |
| :--- | :--- |
| 文字列 | 現在のテキスト位置に文字列を描画し、グリフ幅分だけ前進 |
| 数値 `n` | 横書きでは水平位置を次の式で移動する（単位: テキスト空間の 1/1000） |

$$\Delta x = -\frac{n}{1000} \times \text{fontSize} \times \frac{T_z}{100}$$

> **符号の向きに注意**: **正の値**は文字間を詰める（左へ移動）、**負の値**は文字間を広げる（右へ移動）方向になります。

### 6.6 テキスト行列とテキスト描画位置

テキストブロック内では、テキスト行列（$T_m$）とテキスト描画行列（$T_{rm}$）によって最終座標が決まります。

- **$T_m$（テキスト行列）**: `BT` で単位行列に初期化され、`Tm` で直接設定、`Td` / `TD` / `T*` で相対移動する。
- **$T_{rm}$（テキスト描画位置行列）**:

```text
      [ fontSize * (Tz / 100)   0          0 ]
Trm = [ 0                       fontSize   0 ] × Tm × CTM
      [ 0                       Ts         1 ]
```

## 7. XObject 描画オペレータ

| オペレータ | オペランド | 説明 |
| :--- | :--- | :--- |
| `Do` | `name` | 名前付き XObject（画像またはフォーム）を描画 |

### 7.1 画像 XObject の描画

画像 XObject は常に **$1 \times 1$ の単位正方形**として定義されているため、`cm` で幅・高さ・配置座標を設定してから `Do` を呼びます。

```pdf
q
200 0 0 300 50 400 cm    % 幅 200pt、高さ 300pt、位置 (50, 400) に配置
/Im0 Do                  % 画像を描画
Q
```

### 7.2 フォーム XObject の描画

フォーム XObject は独自の `/Resources`・`/BBox`・`/Matrix` を持ち、独立したサブストリームとして実行されます（入れ子実行の詳細は [04章 §3.2](./04_resources_graphics_state.md#32-xobject外部オブジェクト辞書)）。

```pdf
q
/Fm1 Do                  % フォーム XObject 内のストリームを実行
Q
```

## 8. インラインイメージオペレータ

小さな画像を `/XObject` として別オブジェクト化せず、コンテンツストリーム内に直接埋め込むための特殊構文です。

| オペレータ | 説明 |
| :--- | :--- |
| `BI` | インラインイメージ辞書の開始 |
| `ID` | 画像データの開始（直後に単一のホワイトスペース） |
| `EI` | インラインイメージの終了 |

```pdf
BI
  /W 16 /H 16
  /CS /RGB
  /BPC 8
  /F /Fl
ID
... (バイナリ画像データ) ...
EI
```

#### 省略形キーの対応表

| 省略形 | 完全名 |
| :--- | :--- |
| `/W` | `/Width` |
| `/H` | `/Height` |
| `/BPC` | `/BitsPerComponent` |
| `/CS` | `/ColorSpace` |
| `/F` | `/Filter` |
| `/D` | `/Decode` |
| `/DP` | `/DecodeParms` |
| `/IM` | `/ImageMask` |
| `/I` | `/Interpolate` |

## 9. マーク付きコンテンツオペレータ

タグ付き PDF（アクセシビリティ）、オプショナルコンテンツ（レイヤー）、代替テキストなどの論理構造をコンテンツストリーム上にマークするオペレータです。

| オペレータ | オペランド | 説明 |
| :--- | :--- | :--- |
| `BMC` | `tag` | マーク付きコンテンツの開始（プロパティなし） |
| `BDC` | `tag properties` | プロパティ付きマーク付きコンテンツの開始 |
